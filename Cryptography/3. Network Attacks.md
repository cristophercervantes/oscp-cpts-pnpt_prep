# Evaluating Network Attacks
##  Passive Attacks

A passive attack **doesn't touch the system**. The attacker watches, listens, and collects information — often without the victim ever knowing.

Goals:

- Map the network to find weaknesses
- Capture sensitive data traveling in plain text (usernames, passwords)

> Passive attacks are dangerous not just for what they steal, but because they set up an **active attack** later.

### Reconnaissance — The Scanning Phase

Before striking, an attacker typically runs a series of scans to learn about the target. These don't have to follow a strict order, but generally go like this:

#### 1. Ping Sweep

Sends **ICMP packets** across the network to see which hosts are alive and responding.

```
Attacker → sends ICMP to all IPs → one host replies "I'M HERE"
```

> The name "ping" comes from SONAR — the sound used underwater to detect objects.

#### 2. Port Scan

Once a live host is found, scans its **TCP ports (range 1–1023)** to see what services are running and accepting connections.

```
Example output:
23/tcp  open  telnet
25/tcp  open  smtp
80/tcp  open  http
```

>  Open ports = potential entry points. Network admins should **disable any ports that aren't needed**.

#### 3. OS Fingerprinting

Gathers details from the host's responses to make an educated guess about its **operating system** (e.g., "Windows 10"). Knowing the OS helps the attacker choose the right exploits.

#### 4. Network Mapping

Builds a full **topology map** of the network — identifying all hosts, their IPs, and operating systems.

**Tool to know: Nmap**

> Free, open-source scanner. Can find live hosts, open ports, and services. The same tool used by attackers is also used legitimately by network admins.

### Packet Sniffing (Eavesdropping)

Some passive attacks generate **zero network activity**. The attacker just listens.

**Tool: Wireshark** — open-source packet analysis software.

What an attacker can capture:

- Usernames and passwords sent in **plain text**
- Phone calls, emails, documents
- Device hostnames, IP addresses, OS versions (via protocols like **CDP** and **SSDP**)

**Real example from the chapter:**

```
email=admin%40google.com&password=Password2010
```

That `%40` = the `@` symbol. Credentials exposed in clear text over HTTP.

**Defense:** Encrypt your traffic. If data is encrypted in transit, sniffing it returns garbage.

## Active Attacks

An active attack **does something** — disrupts, modifies, destroys, or steals.

### Social Engineering

Tricks people into doing something harmful — clicking a link, entering credentials on a fake site, etc.

Techniques include: phishing, pharming, fake websites, and popups.

> Social engineering is the **#1 cause of ransomware attacks**. It targets the most vulnerable part of any system: the human.

### Malware Types

|Type|What It Does|
|---|---|
|**Rootkit**|Creates a secret backdoor into the system|
|**Spyware**|Records keystrokes, screenshots, credentials → sends to attacker|
|**Trojan**|Looks like a legit program, hides remote-access code inside|
|**Virus / Worm**|Self-replicates; worms spread on their own; both consume resources|
|**Ransomware**|Encrypts your system and holds it hostage for payment|

> Today's malware is often **polymorphic** — it changes its form and behavior to dodge detection. Hundreds of thousands of new variants are discovered every day.

### DoS / DDoS Attack

A **Denial of Service (DoS)** attack floods a target with so many requests that **legitimate users get locked out**.

The modern version — **DDoS (Distributed DoS)** — uses a massive army of infected machines called **zombies** or **bots**, forming a **botnet**.

**How a botnet works:**

```
1. Attacker infects millions of unknowing hosts with malware
2. Infected hosts become "zombies" in the botnet
3. A Command & Control (C&C) server manages the army
4. At a signal, all zombies flood the target simultaneously
```

> Attacks can occur at **any layer** of the OSI model.

## Protecting Sensitive Data

Data is everywhere — on devices, in the cloud, in IoT systems, even in our cars. Cybercriminals want it for **theft** or **modification** (changing blueprints, IP, etc.).

### What We're Trying to Protect (CIA)

|Goal|Meaning|
|---|---|
|**Confidential**|Protected from unauthorized disclosure|
|**Unaltered**|Not modified, lost, or destroyed|
|**Available**|Accessible by authorized users|

### Common Attack Vectors

An **attack vector** is any path a malicious actor can use to reach your system.

|Vector|Why It's Dangerous|
|---|---|
|**Mobile devices**|Contain photos, banking apps, contacts — a gateway to bigger targets|
|**Wireless networks**|Wi-Fi is inherently insecure; fake hotspots in cafés/airports lure users|
|**The user**|The weakest link — millions fall for phishing, scams, malware daily|
|Email, cloud storage, storage devices|Data at rest and in motion is always a target|

#### Attack Process (Vector → Compromise)

```
1. Find a vulnerable target (using attack vectors)
        ↓
2. Exploit the vulnerability (launch one or multiple attacks)
        ↓
3. Extract sensitive data (passwords, credit card info)
        ↓
4. Create a backdoor (for future access)
```

### Defense Mechanisms

No single method is enough — use a **layered approach**.

|Type|Examples|
|---|---|
|**Logical security**|Access control, authentication (AAA)|
|**Physical security**|Locks, gates, lighting, smartcards|
|**Security appliances**|Firewalls, IDS/IPS, gateways|
|**Policies**|Password rules, acceptable use, antivirus guidelines|

 Even if an attacker bypasses credentials and the firewall, anti-malware protection at the server level can still stop them.

### Security Policies

**Progression:**

```
Security Plan → Security Policies → Security Procedures
```

**When creating a policy, ask:**

- Who is the audience?
- How will it be shared?
- What is the key message?
- Is it regulation-driven?

Write policies in **clear, jargon-free language**. Get upper-management support. Assign someone to enforce and review them regularly.

### The Human Firewall

Since technical defenses keep improving, attackers go after people instead. A skilled attacker will try social engineering **before** attempting password cracking.

**Training your users:**

- Don't click suspicious links
- Be cautious on public Wi-Fi
- Secure mobile devices
- Change passwords regularly; don't reuse them
- Run periodic phishing simulation tests
## Maintaining Integrity

### Assets

|Type|Examples|
|---|---|
|**Tangible**|Computers, servers, printers, cash, furniture|
|**Intangible**|Trade secrets, databases, client lists, brand reputation|

> Intangible assets can be _more_ valuable than tangible ones — and are often harder to monetize when stolen.

### The Risk Formula

```
Risk = Threat × Vulnerability
```

|Term|Definition|Controllable?|
|---|---|---|
|**Threat**|An event or actor capable of causing harm (malware, human error, natural disaster)|❌ No|
|**Vulnerability**|A flaw or weakness (unpatched software, missing AV, human behavior)|✅ Often yes|
|**Risk**|The probability that a threat exploits a vulnerability|✅ Reducible|

> We can't eliminate threats. But by **reducing vulnerabilities**, we **reduce overall risk**.

### Risk Assessment Example

Same threat (malware, 100% probability), different protection levels:

|Protection|Vulnerability|Risk|
|---|---|---|
|Free antivirus, no updates|90%|**90%**|
|Paid antivirus, auto-updates|40%|**40%**|
|UTM appliance, auto-updates|10%|**10%**|

The threat stays constant. The vulnerability — and therefore the risk — drops with better defenses.
