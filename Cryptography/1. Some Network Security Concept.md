## What is Computer Security?

According to **NIST** (National Institute of Standards and Technology, USA):

> _"The protection afforded to an automated information system in order to attain the applicable objectives of preserving the **integrity**, **availability**, and **confidentiality** of information system resources — which includes hardware, software, firmware, information/data, and telecommunications."_

In plain English: we want to keep systems and the data they handle **safe**, **unaltered**, and **accessible** — from the hardware all the way up to the network.

The three bolded words — **Integrity**, **Availability**, **Confidentiality** — are the core of everything. That's what the CIA Triad is about.
## The CIA Triad

```
          +---------------------------+
          |                           |
          |   C  —  Confidentiality   |
          |   I  —  Integrity         |
          |   A  —  Availability      |
          |                           |
          |   (all for: DATA &        |
          |    SERVICES)              |
          +---------------------------+
```

Think of it as the three pillars holding up a secure system. Remove any one of them, and the whole thing becomes vulnerable.

### C — Confidentiality

**The idea:** Only the right people should be able to read the data.

If you send a confidential letter to your friend, only you and your friend should understand it. If a random stranger intercepts and reads it — confidentiality is broken.

**What it prevents:**

- Unauthorized **access** to data
- Unauthorized **disclosure** (exposing the content)

**How it's achieved:**

- **Encryption** — the message gets scrambled into unreadable text. Only the sender and receiver (who have the key) can decrypt it.
- Encryption algorithms are usually made public; it's the **keys** that are kept secret.

```
Sender  ──[plaintext]──►  [ENCRYPT]  ──[ciphertext]──►  [DECRYPT]  ──[plaintext]──►  Receiver
                              ▲                                ▲
                              └────────── Secret Key ──────────┘

                         (Attacker sees only: ████████████)
```

### I — Integrity

**The idea:** What the sender sends = what the receiver gets. No tampering in between.

A simple formula to remember:

```
  SENT  ==  RECEIVED
```

**Why it matters — banking example:**

Imagine you transfer ₹1,000 to a friend. An attacker intercepts the transaction, changes the amount to ₹10,000, and redirects it to their own account. That's an integrity failure.

**What it prevents:**

- Unauthorized **modification** of messages or data
- Redirecting transactions or altering records

**How it works:**

- The security system should be able to **detect** if a message has been changed.
- If tampering is detected → the message is **discarded**.

### A — Availability

**The idea:** The system should be there when you need it — always.

```
  User Request  ──►  Server  ──►  Response 
                       ▲
                 (Should ALWAYS be up,
                  even under attack)
```

**Example::**

- You expect Google to work at 2am. You expect your banking app to respond when you need to check your balance.
- Attackers may launch attacks (like **DDoS**) to take down servers.
- A secure system should **withstand attacks** and still serve users reliably.

## Levels of Impact

When a security breach happens, its severity falls into one of three levels:

| Level      | Effect                      | Description                                                                        |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------- |
| **Low**    | Limited adverse effect      | Minor damage, minor financial loss, negligible harm                                |
| **Medium** | Serious adverse effect      | Significant loss/damage, may involve serious injury or life-threatening situations |
| **High**   | Catastrophic adverse effect | Complete disaster — severe damage to the organization, assets, or individuals      |

> The higher the level, the more critical it is to have security controls in place **before** a breach happens, not after.

## Additional Elements

The classic CIA Triad has 3 elements, but security professionals also recognize two more:

###  Authenticity

**Can you verify who you're talking to?**

When you receive a message, you should be able to confirm it's from a **trusted, genuine source** — not a fake or impersonator.

- Example: When your browser hits `www.google.com`, the server verifies the request came from you (and you trust the response is actually from Google).
- This is the basis of **authentication systems**.

###  Accountability

**Every action should be traceable.**

Every user in a system has specific roles and responsibilities. The system must:

- Keep **logs/records** of all user activity
- Ensure users only access what they're **privileged** to access
- Allow **forensic analysis** later if something suspicious is found

> Think of it as a digital paper trail — if something goes wrong, you can trace back exactly what happened and who did it.

## Threat vs Attack

#### Threat

> _"A potential for violation of security — a possible danger that might exploit a vulnerability."_

- It's a **possibility**, not a certainty
- Exists when there's a circumstance, capability, action, or event that could cause harm
- Example: Having a weak window = threat to your home

#### Attack

> _"An assault on system security — a deliberate attempt, using a method or technique, to evade security services and violate the security policy of a system."_

- It's **intentional and deliberate**
- Attackers are intelligent — they actively look for and exploit vulnerabilities
- Example: Someone actually breaking through your weak window and stealing your belongings

```
  Vulnerability  ──►  Threat  ──►  Attack
  (weak window)      (someone     (break-in
                      could use    happens)
                      this)
```

> **Always think like an attacker.** When building a secure system, ask: _"Is there any way someone could get in?"_ Don't underestimate them.

## The OSI Security Architecture

The OSI Security Architecture is a framework built around **3 components**:

```
┌─────────────────────────────────────────────────────┐
│              OSI Security Architecture               │
│                                                     │
│   1. Security ATTACKS    — what compromises you     │
│   2. Security MECHANISMS — how you fight back       │
│   3. Security SERVICES   — what protection you get  │
│                                                     │
└─────────────────────────────────────────────────────┘
```

Let's break each one down.

## Security Attacks

An **attack** is any action that compromises the security of a system.

Some examples:

- Someone **stealing your information** → attack
- Someone **sniffing your conversation** → attack
- Someone **gaining unauthorized access** to your system → attack
- Someone **taking down a server** so it can't function → attack

Attacks come in **two flavors**:

| Type               | Description                                                           |
| ------------------ | --------------------------------------------------------------------- |
| **Passive Attack** | Attacker _observes_ but doesn't modify anything (e.g., eavesdropping) |
| **Active Attack**  | Attacker _actively alters_ or disrupts data/systems                   |
## Security Mechanisms

A security mechanism is how a system **detects, prevents, or recovers** from an attack.

Think of it as your home's response system:

- **Prevent** → Strong locks, alarms before anyone gets in
- **Detect** → Security camera catches the intruder
- **Recover** → Police notified, belongings retrieved, system restored

```
Attack Happens
     │
     ▼
┌────────────────────────────────────┐
│         Security Mechanism         │
│                                    │
│  Proactive  ──► Prevent the attack │
│  Detective  ──► Detect the attack  │
│  Reactive   ──► Recover from it    │
└────────────────────────────────────┘
```

### Known Security Mechanisms:

- **Encipherment** (encryption)
- **Digital Signatures**
- **Access Control**
- **Data Integrity** checks
- **Authentication Exchange**
- **Traffic Padding**
- **Routing Control**
- **Notarization**
## Security Services

Security services are the **protections a secure system is expected to provide**. These services counter attacks and rely on mechanisms to do so.

| Service                  | What it does                                               |
| ------------------------ | ---------------------------------------------------------- |
| **Authentication**       | Verifies that users/entities are who they claim to be      |
| **Access Control**       | Ensures only authorized users can access resources         |
| **Data Confidentiality** | Keeps data private and hidden from unauthorized parties    |
| **Data Integrity**       | Ensures data isn't tampered with during transmission       |
| **Non-Repudiation**      | Prevents someone from denying they sent/received a message |

## What is a Security Attack?

An **attack** is any action that compromises the security of an individual or an organization.

If an attack lands successfully, the consequences can include:

- Loss or corruption of data
- Ransomware attacks
- Injection of viruses, worms, or malware
- Defacing or taking down servers

All attacks fall into one of two buckets:

```
                    SECURITY ATTACKS
                          │
          ┌───────────────┴───────────────┐
          ▼                               ▼
   PASSIVE ATTACK                  ACTIVE ATTACK
  (just watching)               (modifying/disrupting)
```

## Passive Attacks

> **"Unauthorized reading of messages — no modification involved."**

The attacker's only goal here is to **observe or eavesdrop**. They're not touching the data — just watching it go by.

- Does **not** affect system resources
- Main motive: learn or make use of the information being transmitted
- Goal: **obtain** information, not alter it

There are two types of passive attacks:

### 1. Release of Message Content

The most straightforward one. Alice and Bob are communicating, and **Darth** (the attacker) intercepts and reads the message.

```
Bob ──[message]──────────────────────────► Alice
                        │
                        ▼
                      Darth
                  (reads the message)
```

**What Darth gets:** The actual content of the conversation.

**How to prevent it:** Encrypt the message. If Bob encrypts before sending, Darth only sees scrambled text and can't understand a thing.

```
Bob ──[🔒 encrypted]────────────────────► Alice
                        │
                        ▼
                      Darth
                  (sees: ██████████)
                  (understands: nothing)
```

### 2. Traffic Analysis

Bob and Alice are smart — they've started encrypting everything. Darth can no longer read the content. But he's still watching...

```
Bob ──[🔒 encrypted]────────────────────► Alice
                        │
                        ▼
                      Darth
            Can't read content, BUT observes:
            ├── Who is talking to whom?
            ├── How often are they communicating?
            ├── How large are the messages?
            └── What time do they communicate?
```

**What Darth gets:** Even without reading the content, the _pattern_ of communication reveals a lot. Frequent large messages between two parties might hint at something significant going on.

Encryption protects content, but metadata and traffic patterns can still leak information.

##  Active Attacks

> **"Involves modification of data streams or creation of false data streams."**

Unlike passive attacks, active attacks are hands-on. The attacker isn't just watching — they're **doing something**. This makes them easier to detect but harder to prevent.

There are 4 types:

### 1. Masquerade

> _One entity pretends to be a different entity._

Think of it like stealing someone's ID card and using it to get into a building. The system sees the ID and lets you in — it has no way of knowing it's not the real person.

```
Bob (authorized) ──── [has privileges]

  Darth steals Bob's credentials
        │
        ▼
Darth ──[pretending to be Bob]──► Alice
Alice thinks: "Oh, this is Bob!"
```

**Real-world example:** Logging in with someone else's stolen username and password.

A masquerader can also _demand extra privileges_ by pretending to be someone with higher access. Even if the real Bob only had limited permissions, Darth (pretending to be Bob) might try to escalate.

### 2. Replay

> _Captured messages are retransmitted later to produce an unauthorized effect._

Darth doesn't even need to understand the message. He just saves it and sends it again.

```
Step 1:  Bob ──[message]──► Alice
                   │
                Darth captures it

Step 2:    Darth ──[same message, again]──► Alice
                   (and again... and again...)
```

Imagine Bob sends an authenticated request to transfer money. Darth captures it and replays it 10 times. The server processes it each time — Bob gets charged repeatedly.

### 3. Modification of Messages

> _The original message is altered before reaching the receiver._

Darth catches the message mid-flight, changes part of it, and forwards the modified version.

```
Bob sends:    "Allow Jon to edit the document"
                           │
                        Darth intercepts
                      changes "Jon" → "Tim"
                           │
Alice receives: "Allow Tim to edit the document"
```

```
Bob ──[original]──►   Darth ──[modified]──► Alice
                    (edits content here)
```

Alice has no idea the message was tampered with. She acts on wrong information.

### 4. Denial of Service (DoS)

> _Prevents or inhibits the normal use of communication facilities._

The goal here isn't to steal data — it's to **crash the service** so legitimate users can't access it.

```
Normal situation:
Bob ──[request]──► Server ──[response]──► Bob 

Under DoS attack:
  Darth floods server with thousands of fake requests
        │
        ▼
Server is overwhelmed 
        │
Bob ──[request]──► Server ──[no response]──► Bob 
```

**A common DoS technique — TCP SYN Flood:** Darth creates a malicious bot that sends thousands of TCP connection requests to the server. The server thinks these are all from different legitimate clients (the requests are spoofed). At some point, the server is so overloaded it can't handle any real requests.
## Passive vs Active

| Feature                  | Passive Attack                  | Active Attack            |
| ------------------------ | ------------------------------- | ------------------------ |
| **Message modification** | No                              | Yes                      |
| **Ease of detection**    | Hard                            | Easier                   |
| **Ease of prevention**   | Easier (via encryption)         | Hard                     |
| **What to focus on**     | **Prevention**                  | **Detection & Recovery** |
| **Effect on system**     | No direct effect                | Disrupts/damages system  |
| **Examples**             | Eavesdropping, traffic analysis | Masquerade, replay, DoS  |

### Why passive attacks are hard to detect:

If nobody modifies the message, how do you even know someone read it? Imagine 10 people read your letter before it reached your friend — but folded it back neatly each time. You'd never know.

### Why active attacks are hard to prevent:

You can't know exactly _how_ or _when_ an attacker will strike. Physical, software, or network vulnerabilities can all be exploited. The best you can do is detect fast and recover quickly.

## What are Security Services?

> _"A processing or communication service provided by a system to give a specific kind of protection to system resources."_

In plain terms: security services are the **promises** a secure system makes to its users. They define _what_ the system will protect, and _how_.

Two important things to remember:

- Security services **implement security policies**
- They are **delivered through security mechanisms** (encryption, digital signatures, etc.)

```
Security Policy
      │
      ▼
Security Services  ◄──── "What protection do we provide?"
      │
      ▼
Security Mechanisms ◄─── "How do we deliver it?"
```

There are **5 security services** defined in the OSI framework:

## 1. Authentication

> _"Assurance that the communicating entity is the one it claims to be."_

Authentication answers the question: **"Are you really who you say you are?"**

When Alice receives a message from Bob, she needs to be sure it's actually _from_ Bob — not from Darth pretending to be Bob.

```
Bob ──[message]──► Alice
                     │
                     ▼
              "Is this really from Bob?"
              Authentication service verifies 
```

There are **two types** of authentication:

### Peer Entity Authentication

Verifies the identity of the other party during an **active communication session**.

```
Bob ←──────────────────────► Alice
     "I am Bob"        "Prove it →  Verified"

(Used during connection setup or data transfer)
```

### Data Origin Authentication

Verifies where a piece of data **came from** — but doesn't necessarily involve a live session.

```
Alice receives a message ──► "Who sent this?"
                              Authentication traces it back to Bob 
```

> **Why it matters:** Without authentication, Darth can impersonate anyone. This service is the foundation of trust in any communication.

## 2. Access Control

> _"Prevention of unauthorized use of a resource."_

Access control determines **who can do what** within a system. Not every user should have access to everything.

```
System Resources
      │
      ├── Admin Panel       ← Only: System Admin
      ├── Customer Records  ← Only: Manager + Teller
      ├── Loan Files        ← Only: Manager
      └── Basic Transactions← Anyone logged in
```

### Banking Example

In a bank's system:

- The **Bank Manager** has access to everything — loan approvals, salary records, customer data
- The **Bank Teller** has access to day-to-day transactions only
- A **Customer** can only see their own account

Every user is assigned a **level of privilege**, and the access control service ensures they can't exceed it.

```
User Login
    │
    ▼
Access Control Check
    │
    ├── Has permission? ──► Allow access
    └── No permission?  ──► Deny access
```
## 3. Data Confidentiality

> _"Protection of data from unauthorized disclosure."_

This is the **C** in the CIA Triad, now viewed as a formal security service. Data confidentiality ensures that only authorized parties can read the data being transmitted.

```
Bob ──[plaintext: "Transfer ₹5000"]──► Anyone can read this

Bob ──[encrypted: "X7#kP!2q@"]──────►   Only Alice can decrypt
                                           Darth sees: nothing useful
```

**How it's achieved:** Primarily through **encryption**. The data is scrambled before transmission, and only the intended recipient (with the correct key) can unscramble it.

### Levels of Confidentiality:

|Level|What's Protected|
|---|---|
|Connection confidentiality|All data on a connection|
|Connectionless confidentiality|Individual data packets|
|Selective field confidentiality|Specific fields within a message|
|Traffic flow confidentiality|Even hides the _pattern_ of communication|

## 4. Data Integrity

> _"Assurance that data received is exactly as sent — no modification, insertion, deletion, or replay."_

This is the **I** in the CIA Triad as a service. The system guarantees that whatever Bob sent, Alice receives _exactly_ — untampered.

```
Bob sends:     "Allow Jon to edit the file"
                         │
                      Darth tries to modify
                         │
Data Integrity check ──►   Modification detected!
                             Message discarded.

Alice receives: [nothing — system blocked the tampered message]
```

**What it protects against:**

- Modification of messages (active attack)
- Insertion of fake data into a stream
- Deletion of parts of a message
- Replay attacks (sending old messages again)

## 5. Non-Repudiation

> _"Protection against denial by one of the parties in a communication — proof that a message was sent and received."_

Non-repudiation prevents someone from later claiming _"I never sent that"_ or _"I never received that."_

It works at **two levels:**

```
Source Level (Sender can't deny sending):
Bob sends a message ──► System creates proof Bob sent it
Later Bob says: "I didn't send that!"
System shows:   "Yes you did. Here's the proof." 

Destination Level (Receiver can't deny receiving):
Alice receives message ──► System creates proof Alice got it
Later Alice says: "I never received it!"
System shows:    "Yes you did. Here's the proof." 
```

**Real-world analogy:** It's like a courier service that requires the receiver's signature. The signature is _proof of delivery_ — the receiver can't later claim they never got the package.

## How They All Connect

These 5 services work together to cover all aspects of secure communication:

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  THREAT          SERVICE THAT COUNTERS IT               │
│                                                         │
│  Impersonation ──────► Authentication                   │
│  Unauthorized access ► Access Control                   │
│  Eavesdropping ──────► Data Confidentiality             │
│  Tampering ──────────► Data Integrity                   │
│  Denial of action ───► Non-Repudiation                  │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

No single service is enough on its own — a complete secure system implements all of them.

### What is a Security Mechanism?

Security mechanisms are the **tools and techniques** used to implement security policies and protect data. Think of them like locks, guards, and cameras for your computer system.

There are **2 types:**

1. **Specific Security Mechanisms**
2. **Pervasive (General) Security Mechanisms**

### Specific Security Mechanisms

#### 1.  Cryptography

Converts readable data (plain text) into unreadable form using **mathematical algorithms**. Since the math is very strong, hackers can't easily break it.

> Example: Your WhatsApp messages are encrypted so only the receiver can read them.

#### 2. Digital Signature

A way to **verify the identity** of the sender. It also ensures the data was **not modified** during transmission. It provides both **Authentication + Data Integrity**.

#### 3. Access Control

Controls **who can access what**. Not every user gets access to everything. Different users get different levels of permission.

#### 4. Data Integrity

Ensures the data received is **exactly the same** as what was sent — nothing was changed in between.

#### 5. Authentication Exchange

Two parties **exchange small pieces of information** to prove they are legitimate (real) users and not attackers.

#### 6. Traffic Padding

Fake/dummy data is added to the network to **confuse attackers** so they can't figure out the real data pattern.

#### 7. Routing Control

Data travels through **specific secure routes** in the network, so it can be physically protected.

#### 8. Notarization

A **trusted third party** (like a Certificate Authority) steps in to **resolve disputes** between sender and receiver and issues certificates (like SSL certificates).

### Pervasive (General) Security Mechanisms

These are **not tied to any specific layer** — they work across the whole system.

#### 1. Trusted Functionality

Actions are checked against **security policies** to decide if they are allowed or not.

#### 2. Security Labels

Resources are given **labels** to identify their security level and who can access them.

#### 3. Event Detection

The system monitors all activities and detects **suspicious or abnormal events** — helping identify if a legitimate user or an attacker is doing something.

#### 4. Security Audit Trail

All activities are **recorded and reviewed regularly** (like a CCTV recording) to check whether everything is normal or suspicious.

#### 5. Security Recovery

If a system is **attacked or data is lost**, this mechanism helps **restore the system** back to its original state.
