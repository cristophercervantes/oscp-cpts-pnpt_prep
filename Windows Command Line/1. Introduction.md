### **Windows Command Line Fundamentals 

Windows provides two main built-in command-line interfaces:

- **CMD.exe** (Command Prompt)
- **PowerShell**

Both are extremely important for system administration **and** penetration testing. As pentesters, we use them for reconnaissance, privilege escalation, lateral movement, data exfiltration, and automation.

#### **Command Prompt vs PowerShell 

|Feature|**Command Prompt (CMD)**|**PowerShell**|
|---|---|---|
|Introduced|1981|2006|
|Command Style|Only batch commands|Cmdlets + can run batch commands too|
|Output Format|Plain text|**Objects** (much more powerful)|
|Piping|Limited|Excellent – output of one cmdlet can go to another|
|Aliases|Not supported|Supported|
|Scripting Capabilities|Very basic|Full scripting language with ISE|
|.NET Framework Access|No|Yes (very powerful)|
|Cross-Platform|Windows only|Works on Linux and macOS too|
|Modern Usage|Legacy / simple tasks|Preferred for advanced administration & automation|

**CMD is old, simple, and static. **PowerShell** is modern, object-oriented, and extremely powerful — it’s the tool you’ll use most in real engagements.

You can run CMD commands inside PowerShell, but to run PowerShell commands from CMD, you must prefix them with powershell.

Once we gain initial access (a shell) on a Windows machine, we rely heavily on built-in tools and commands because:

- We may not be able to upload new tools
- Antivirus/EDR may block third-party tools
- Living-off-the-land (using built-in tools) is stealthier

We use CMD and PowerShell for:

- Reconnaissance & enumeration
- Privilege escalation
- Lateral movement
- Data discovery and exfiltration
- Persistence
- Automation
