## Cyber Defense
- A subsection of cybersecurity
- Different from corporate cybersecurity
- Focuses on **resisting attacks**
- Mission-driven (more governmental)
- Involves:
  - Intelligence
  - Planning
  - Surveillance
  - Penetration testing
  - Forensics

## Information Security Policies
- Rules to ensure **CIA** (Confidentiality, Integrity, Availability) of IT infrastructure
- **Objectives**: Secure digital assets, comply with rules
- **Scope**: Varies, sometimes hierarchical
- **Implementation**:
  - Workers sign agreements
  - Apply necessary changes
  - Trainings & evaluations organized
- **Example**: Encrypting databases → all responsible parties informed
- **Key Insight**: **People are the weakest link**
- Aligned with company goals
- Applicable only within organizational authority

## Vulnerability Research
> *"Security engineers see the world differently than other engineers."*

### Approach
- **White-box** software testing

### Steps
1. Fuzzing & Reverse Engineering
2. Network & Protocol Analysis
3. Cryptography
4. Web Apps, APIs, Mobile Apps
5. Hardware Analysis

### Key Concepts
- Understand **how a system works (X)**
- Understand **how a system fails (Y)**
- Can be done by good or bad actors
- Derive concepts from known attacks → apply statistically
- Periodic operations reduce zero-day exploits

## Operating Systems: Linux

### Overview
- Open-source, cross-platform
- Derived from **UNIX**, created by **Linus Torvalds** (1991)
- Most widely used **kernel**
- Runs on:
  - Smartphones
  - Laptops
  - Servers
  - Appliances
  - Submarines
  - Space rockets
- UNIX shell-based environment
- Just a **kernel**

### Evolution
| Year | Event |
|------|-------|
| 1969 | UNIX started at Bell Labs (C language) |
| 1980s | Large orgs developed proprietary UNIX dialects |
| 1991 | Torvalds creates free UNIX alternative |
| 1992 | Linux under **GNU GPL** (non-commercial) |
| 1990s+ | Many **distributions** emerge |

## Penetration Testing
- **Authorized simulated cyberattack**
- Evaluates system security
- Manual or automated
- Checks:
  - Compliance
  - Employee awareness
  - Incident resilience
- **Ethical Hacking** = Learning  
  **Penetration Testing** = Implementing

### Phases of Penetration Testing

| Phase                  | Activities |
|------------------------|----------|
| **Pre-Engagement**     | Client meeting, scope definition |
| **Planning & Recon**   | Test plan, public info gathering |
| **Threat Modeling**    | Rank vulnerabilities |
| **Exploitation**       | Breach via bugs/exploits |
| **Post-Exploitation**  | Assess impact, propagate |
| **Reporting**          | Detail findings, impact, fixes |
| **Resolution & Retest**| Fix issues, verify |

## Dual Boot vs Virtual Machine

| Feature               | **Dual Boot**                        | **Virtual Machine**                   |
|-----------------------|--------------------------------------|---------------------------------------|
| Resource Access       | Full dedicated hardware              | Shared resources                      |
| Performance           | Best for heavy tasks (gaming, etc.)  | Slower for intensive apps             |
| Setup                 | Complex, risky                       | Easy, safe (sandboxed)                |
| Switching OS          | Requires reboot                      | Instant switch                        |
| Security              | Direct exposure                      | Extra layer (snapshots, isolation)    |
| Portability           | Tied to hardware                     | Move VMs easily                       |

## VM Networking Modes

| Mode           | Behavior |
|----------------|--------|
| **NAT**        | VM in private subnet<br>Internet access<br>No external access to VM<br>Internal DHCP |
| **Bridged**    | VM on same network as host<br>Accessible by LAN<br>External DHCP |
| **Host-Only**  | Private network inside host<br>VMs talk to each other & host<br>No internet |
| **LAN Segment**| Internal network<br>VMs talk to each other<br>**Not** to host |
