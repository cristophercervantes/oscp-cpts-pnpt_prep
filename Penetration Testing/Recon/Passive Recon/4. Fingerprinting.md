## **Fingerprinting**

> **Fingerprinting** is the process of extracting technical details about the technologies powering a website or web application. By identifying server software, operating systems, and other components, an attacker can tailor exploits to the target’s specific stack.

- **Targeted Attacks** – Focus on known vulnerabilities for the identified technologies.
    
- **Misconfiguration Discovery** – Reveal outdated software, default settings, or other weaknesses.
    
- **Prioritisation** – Helps choose the most promising targets among many.
    
- **Comprehensive Profiling** – Combines with other reconnaissance data for a full infrastructure view.
    

### **Fingerprinting Techniques**

|                                |                                                                        |                                                     |
| ------------------------------ | ---------------------------------------------------------------------- | --------------------------------------------------- |
| Technique                      | What It Does                                                           | Typical Indicators                                  |
| **Banner Grabbing**            | Reads service banners from open ports.                                 | Server name and version in responses.               |
| **Analyzing HTTP Headers**     | Inspects headers like Server and X‑Powered‑By.                         | Reveals web server, scripting language, frameworks. |
| **Probing Specific Responses** | Sends crafted requests to trigger unique error messages or behaviours. | Error pages, redirects, custom responses.           |
| **Analyzing Page Content**     | Looks at HTML, scripts, and meta tags for clues.                       | Copyright notices, wp‑ prefixes, hidden files.      |

### Common Fingerprinting Tools

|                |                                                  |                                                     |
| -------------- | ------------------------------------------------ | --------------------------------------------------- |
| Tool           | Description                                      | Notable Features                                    |

## **Fingerprinting** practical

### **Banner Grabbing**

```bash
curl -I inlanefreight.com
```

Result (truncated):

```
HTTP/1.1 301 Moved Permanently
Server: Apache/2.4.41 (Ubuntu)
Location: https://inlanefreight.com/
```

- **Web server**: Apache/2.4.41 (Ubuntu)
    
- Redirects to HTTPS.
    

```bash
curl -I https://inlanefreight.com
```

Result shows an additional header:

```
X-Redirect-By: WordPress
```

```bash
curl -I https://www.inlanefreight.com
```

Result includes WordPress‑specific Link headers pointing to wp‑json endpoints, confirming a **WordPress** installation.

### **WAF Detection with** **wafw00f**

```bash
pip3 install git+https://github.com/EnableSecurity/wafw00f
wafw00f inlanefreight.com
```

Output indicates protection by **Wordfence Web Application Firewall** (developed by Defiant). This layer may block or filter further probes.

### **Nikto Scan (Software Identification)**

```bash
nikto -h inlanefreight.com -Tuning b
```

findings:

- **IP addresses**: 134.209.24.248 (IPv4) and 2a03:b0c0:1:e0::32c:b001 (IPv6).
    
- **Server**: Apache/2.4.41 (Ubuntu).
    
- **WordPress** detected; login page at /wp-login.php.
    
- **License file** (/license.txt) present – may disclose software details.
    
- **Missing security headers**: No Strict-Transport-Security and no X‑Content‑Type‑Options.
    
- **Potential issues**:
    
    - Content-Encoding: deflate could be vulnerable to the **BREACH** attack.
        
    - Apache version is outdated (latest ≥ 2.4.59).
        
    - Cookie wordpress_test_cookie lacks the HttpOnly flag.
        
    - X-Frame-Options deprecated; should use Content‑Security‑Policy with frame‑ancestors.
