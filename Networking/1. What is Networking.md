## What the internet actually is

The internet is not a cloud or a magical entity — it is a physical interconnection of computers around the world, linked together like a giant spider web.

A **network** is any group of computers connected to communicate with each other. Two computers connected together is a network. Your home devices, your workplace computers, your school — all networks. Connect those networks together, and eventually you get billions of interconnected computers: the internet.

## Internet vs World Wide Web

These are not the same thing.

- **Internet** — the physical infrastructure: cables, satellites, cellular networks, the actual connections between machines
- **World Wide Web** — the information and websites that live on the internet, accessed through a browser

Email, chat apps, and file sharing are also ways to use the internet — the web is just one of them.

## How the internet is structured

**Servers** — computers that connect directly to the internet and store content (websites, files, etc.)

**Clients** — the devices we use: phones, laptops, game consoles. Clients do not connect directly to the internet.

**ISPs (Internet Service Providers)** — clients connect to a network run by an ISP (like Comcast or AT&T). ISPs have built and maintain the physical infrastructure that connects millions of devices. ISPs connect to each other, forming the broader internet.

## IP addresses and MAC addresses

Every device on a network needs identifiers so data reaches the right place.

**IP address** — the location identifier. Like a house address. Example: `172.217.6.46`. Can change depending on the network.

**MAC address** — the device identifier. Hard-coded into the hardware, generally permanent. Example: `82:4f:23:59:47:4`. Like the name on a letter.

You need both to send and receive data — the IP gets it to the right location, the MAC gets it to the right device at that location.

## How data travels — packets

Data sent across a network is broken into small chunks called **packets** — ones and zeros. It doesn't matter if it's an image, email, music, or text — it all gets broken into packets.

Each packet travels independently, finding its way hop by hop toward the destination. Once all packets arrive, they reassemble in order.

The analogy: like a letter traveling from New York to Tokyo through multiple post offices. Each stop doesn't need to know the full route — just the next closest destination to pass it along. Eventually it arrives.

# Network Connections and Devices

## Three ways to connect to a network

**Ethernet cable** — physical connection. Plug a cable into the network port on the back of a computer. Reliable and fast.

**Wi-Fi** — wireless networking. Uses radios and antennas. Built into most modern devices — phones, laptops, smart TVs.

**Fiber optic** — the fastest and most expensive option. Cables contain glass fibers that transmit data as light rather than electricity. Ones and zeros travel as beams of light instead of electrical current through copper wire.

## Network devices — how computers are organized together

**Router** Connects multiple devices and routes traffic between them. When you send a packet, the router figures out where it needs to go — either within your network or out to another network. Routers handle traffic between different networks.

**Switch** Like a mail room inside a building. Once the router gets your data to the right building (network), the switch figures out which specific device inside to send it to.

**Hub** Broadcasts data to every device on the network — like a company-wide memo. It doesn't know who specifically should receive the data, so everyone gets it. Less efficient than a switch.

## Troubleshooting networks — the network stack

When users report internet or connectivity problems, you work your way up the network stack — the set of hardware and software that makes up the network infrastructure.

Order to investigate:

1. End user's computer — is it working properly?
2. Cabling — is it connected and undamaged?
3. Switch — is the local network device functioning?
4. Router — is traffic being routed correctly?
5. ISP connection — is the path out to the internet intact?

## Network protocols — the rules of data transfer

Protocols are rules that govern how data moves across a network — ensuring packets are routed correctly, arrive uncorrupted, go to the right machine, and are handled securely.

Two protocols that underpin the internet:

**IP — Internet Protocol** Handles delivery — gets packets to the right computer using IP addresses.

**TCP — Transmission Control Protocol** Handles reliable delivery — makes sure data gets from one network to another without errors.

Together they are referred to as **TCP/IP** — the foundation of how the internet works.

## Websites and HTML

Websites are text documents formatted with **HTML (HyperText Markup Language)** — the language web browsers read and render. Web pages contain a mix of text, images, audio, and video.

## URLs — web addresses

A URL (Uniform Resource Locator) is a web address. Breaking one down using `www.reddit.com`:

|Part|What it is|
|---|---|
|`www`|World Wide Web|
|`reddit`|Domain name — the website's registered name|
|`.com`|Top-level domain — indicates the type of site|

Common top-level domains:

- `.com` — commercial
- `.org` — organizations
- `.edu` — educational institutions
- `.net` — network-related

Domain names are registered with **ICANN (Internet Corporation for Assigned Names and Numbers)**. Once registered, no one else can use that name unless it becomes available again.

## DNS — Domain Name System

Computers don't understand `google.com`. They only understand IP addresses like `172.217.6.46`. DNS is the system that translates human-readable domain names into IP addresses.

Every time you visit a website, your computer performs a **DNS lookup** — it asks the DNS system "what is the IP address for this domain name?" and then connects to that IP.

DNS acts as the internet's directory.

## DNS troubleshooting tip

If you can access a website by typing its IP address directly into the browser but not by its domain name, the problem is likely in the DNS configuration of the network — not the website itself.

This is a quick and useful first diagnostic step when investigating connectivity issues.
