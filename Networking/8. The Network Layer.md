# The Network Layer and IP

MAC addresses work well on a local area network (LAN). A switch learns which MAC addresses are connected to which of its ports and routes frames accordingly. But MAC addressing doesn't scale:

- Every network interface on the planet has a unique MAC address
- MAC addresses are not ordered in any systematic way — there's no way to know where a given MAC address is located geographically
- The way nodes learn each other's MAC addresses (ARP — Address Resolution Protocol) only works within a single network segment

MAC addressing is designed for local communication. It cannot route traffic across different networks. A different solution is needed for inter-network communication.

## The solution — the Network Layer and IP

The **Network Layer (Layer 3)** solves this problem through the **Internet Protocol (IP)** and IP addresses.

IP addresses are structured and hierarchical — unlike MAC addresses, they encode location information that allows routers to determine the path traffic should take across multiple networks.

## IP datagrams and encapsulation

When IP is used to send data, it packages the data into an **IP datagram**. That datagram is then placed into the **payload of an Ethernet frame** for transmission across a physical link.

This is encapsulation — each layer wraps the layer above it:

```
Ethernet Frame
  └── Payload: IP Datagram
        └── Payload: Transport layer data (TCP/UDP segment)
              └── Payload: Application data
```

The Ethernet frame handles getting data across a single link. The IP datagram handles getting data across multiple networks to the right destination.

# IP Addresses
## IP address format

An IP address is a **32-bit number** made up of four octets, written in **dotted decimal notation**.

Each octet is 8 bits, which can represent any decimal number from **0 to 255**.

Example of a valid IP address: `12.34.56.78` Example of an invalid IP address: `123.456.789.100` — numbers above 255 cannot be represented in 8 bits.

## How IP addresses are assigned 

Unlike MAC addresses (assigned by hardware manufacturers in no particular order), IP addresses are distributed in large blocks to organizations and companies. This makes them **hierarchical**, which is the key to routing at scale.

Example: IBM owns every IP address starting with `9` as the first octet. When a router needs to forward traffic to `90.0.0.1`, it only needs to know to send it toward IBM's network. IBM's routers handle delivery from there.

This hierarchical structure means routers don't need to know the exact location of every device on the internet — just the general direction, getting progressively more specific at each hop.

## IP addresses belong to networks, not devices

A device's MAC address never changes — it's burned into the hardware. But its IP address changes depending on which network it's connected to.

Your laptop has the same MAC address everywhere, but it gets a different IP address at home than it does at a café. Each local network is responsible for assigning IP addresses to devices that connect to it.

## Dynamic vs. static IP addresses

**Dynamic IP address** — assigned automatically by the network using **DHCP (Dynamic Host Configuration Protocol)**. The process is mostly invisible to the user. Most client devices (laptops, phones) use dynamic IP addresses.

**Static IP address** — configured manually on a device. Doesn't change. Typically used for servers and network devices that need a consistent, known address.

Most networks use dynamic for clients and static for servers and infrastructure, though exceptions exist.

# IP Datagram Structure

An IP datagram is the name for a data packet at the network layer (Layer 3). Like an Ethernet frame, it is a highly structured series of strictly defined fields, divided into a **header** and a **payload**.

## IP datagram header fields

### Version (4 bits)

Which version of IP is being used. Most common: **IPv4**. IPv6 is seeing increasing adoption.

### Header Length (4 bits)

How long the header itself is. Almost always **20 bytes** for IPv4 — the minimum possible size to fit all required header data.

### Service Type (8 bits)

Used to specify **Quality of Service (QoS)** details. Allows routers to prioritize certain datagrams over others when the network is congested.

### Total Length (16 bits)

The total length of the entire IP datagram. Since this field is 16 bits, the maximum size of a single datagram is **65,535 bytes**.

### Identification (16 bits)

A number used to group related packets together. When a large piece of data exceeds the maximum datagram size and has to be split across multiple datagrams, all fragments share the same identification value so the receiving end knows they belong together.

### Flag field

Indicates whether a datagram is allowed to be fragmented, or signals that it already has been. **Fragmentation** is the process of splitting one large datagram into smaller ones — necessary when crossing from a network that allows larger datagrams to one that doesn't.

### Fragmentation Offset field

Contains values the receiving end uses to reassemble fragmented packets in the correct order.

### TTL — Time to Live (8 bits)

Indicates how many router hops the datagram can make before being discarded. Every router that receives the datagram decrements this value by 1. When it reaches 0, the router drops it.

Purpose: prevents datagrams from looping forever when there is a routing misconfiguration (e.g. Router A thinks Router B is the next hop, Router B thinks Router A is the next hop).

### Protocol (8 bits)

Specifies which transport layer protocol the payload uses. Most common: **TCP** and **UDP**.

### Header Checksum

A checksum of the entire IP header — used to verify header integrity. Because the TTL field changes at every router hop, this checksum is recalculated at every router.

### Source IP Address (32 bits)

The IP address of the sender.

### Destination IP Address (32 bits)

The IP address of the intended recipient.

### IP Options (variable, optional)

Used to set special characteristics for datagrams. Primarily used for testing purposes. Rarely seen in normal traffic.

### Padding

A series of zeroes following the IP Options field to ensure the header is the correct total size.

## Header fields 

|Field|Size|Purpose|
|---|---|---|
|Version|4 bits|IPv4 or IPv6|
|Header Length|4 bits|Length of the header (typically 20 bytes)|
|Service Type|8 bits|QoS / priority|
|Total Length|16 bits|Size of entire datagram (max 65,535 bytes)|
|Identification|16 bits|Groups fragmented packets together|
|Flags|3 bits|Fragmentation allowed / already fragmented|
|Fragmentation Offset|13 bits|Reassembly order for fragments|
|TTL|8 bits|Max router hops before discard|
|Protocol|8 bits|TCP, UDP, or other transport protocol|
|Header Checksum|16 bits|Header integrity verification|
|Source IP|32 bits|Sender's IP address|
|Destination IP|32 bits|Recipient's IP address|
|IP Options|Variable|Special characteristics (optional)|
|Padding|Variable|Fills header to correct size|

## Encapsulation — how it all fits together

The IP datagram sits inside an Ethernet frame as its payload:

```
Ethernet Frame
  └── Payload: IP Datagram (header + payload)
        └── Payload: TCP or UDP packet
              └── Payload: Application data
```

Each layer is needed for the one above it. The Ethernet frame handles the physical link. The IP datagram handles routing across networks. The TCP/UDP packet handles delivery to the correct application.

# IP Address Classes
## Network ID vs Host ID

Every IP address is divided into two parts:

- **Network ID** — identifies which network the address belongs to
- **Host ID** — identifies the specific device on that network

## The address class system

The address class system defines how the global IP address space is split up based on where the network/host boundary falls.

|Class|Network ID octets|Host ID octets|First octet range|Total host addresses|
|---|---|---|---|---|
|A|First octet|Last three|0–127|2²⁴ = 16,777,216|
|B|First two octets|Last two|128–191|2¹⁶ = 65,536|
|C|First three octets|Last octet|192–223|2⁸ = 256|
|D|—|—|224–239|Used for multicasting|
|E|—|—|240–255|Reserved for testing, unassigned|

## How to identify the class from the address

**In binary:**

- First bit is `0` → Class A
- First bits are `10` → Class B
- First bits are `110` → Class C
- First bits are `1110` → Class D

**In dotted decimal (easier):**

- First octet 0–127 → Class A
- First octet 128–191 → Class B
- First octet 192–223 → Class C

Example: `9.100.100.100` — first octet is 9 (falls in 0–127) → Class A. Network ID = `9`, Host ID = `100.100.100`.

## Class D and E

**Class D** — used for **multicasting**, where a single IP datagram is sent to an entire network at once. Addresses start with bits `1110` (decimal 224–239).

**Class E** — reserved for testing purposes only. Not used in real networks.

## CIDR has mostly replaced the class system

In practice, the rigid address class system has been largely superseded by **CIDR (Classless Inter-Domain Routing)**, which allows more flexible allocation of IP address space. However, the class system remains foundational knowledge and is still relevant in many contexts.

# ARP — Address Resolution Protocol

An IP datagram needs to be encapsulated in an Ethernet frame before it can be transmitted. The Ethernet frame header requires a **destination MAC address**. But when a device knows the destination's IP address, it doesn't necessarily know the corresponding MAC address. ARP bridges this gap.

## What ARP does

**ARP (Address Resolution Protocol)** discovers the hardware (MAC) address of a node when you know its IP address.

## How it works

1. A device wants to send data to IP address `10.20.30.40`
2. It checks its local **ARP table** — a list mapping IP addresses to MAC addresses
3. If there's no entry for `10.20.30.40`, it sends an **ARP broadcast** to the MAC broadcast address (`FF:FF:FF:FF:FF:FF`) — delivered to every device on the local network
4. The device that has been assigned IP `10.20.30.40` receives the broadcast and replies with an **ARP response** containing its MAC address
5. The transmitting device now has the MAC address it needs to complete the Ethernet frame
6. The IP-to-MAC mapping is stored in the ARP table for future use — so the broadcast doesn't need to happen again next time

## ARP table

A local cache of IP-to-MAC address mappings maintained by every network-connected device. Entries **expire after a short time** to account for changes in the network (devices moving, IP reassignment, etc.).

## ARP only works on the local network

ARP operates at Layer 2 and is limited to a single network segment. It cannot be used to discover MAC addresses across different networks — this is part of why IP addressing exists at a higher layer.
