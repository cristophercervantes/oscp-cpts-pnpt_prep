### Transport Layer — Multiplexing & Demultiplexing

Transport layer functions: multiplexing/demultiplexing, connection establishment, reliability via error checking and data verification.

#### Multiplexing vs Demultiplexing

- **Multiplexing** — directing outbound traffic from a node to many different receiving services
- **Demultiplexing** — receiving-end equivalent: taking traffic aimed at one node and delivering it to the correct service
- Unique to the transport layer among the OSI layers
- Achieved through **ports**

#### Ports

- 16-bit number used to direct traffic to a specific service on a networked host
- Server/service = program listening for requests; client = program requesting data
- Combined with an IP, written as a **socket address**: `IP:port` (e.g. `10.1.1.100:80`)

#### Common Port Examples

|Port|Service|
|---|---|
|80|HTTP (unencrypted web traffic)|
|21|FTP (file transfer)|

### TCP Segment Structure

TCP segment = TCP header + data section. Encapsulation chain: Ethernet frame → IP datagram → TCP segment.

#### Header Fields

|Field|Size|Purpose|
|---|---|---|
|Source port|16-bit|Ephemeral port; keeps outgoing connections separate, lets replies reach the right requesting program|
|Destination port|16-bit|Port of the intended service (e.g. port 80 for web)|
|Sequence number|32-bit|Tracks this segment's position in a sequence of segments|
|Acknowledgment number|—|Number of the next expected segment|
|Data offset|4-bit|Length of the TCP header, so receiver knows where data payload starts|
|Control flags|6 bits|Reserved for the six TCP flags|
|Window|16-bit|Range of sequence numbers that can be sent before an ACK is required|
|Checksum|16-bit|Validates segment integrity (same concept as IP/Ethernet checksums)|
|Urgent pointer|—|Marks higher-priority segments (used with a control flag); rarely adopted in practice|
|Options|—|Rarely used; supports more complex flow-control protocols|
|Padding|—|Zeros to align the start of the data payload|

#### The reason of Segmentation 

- Lower layers cap frame size (Ethernet ≈ 1,518 bytes)
- TCP splits larger data into multiple segments
- Sequence number tracks each segment's place in that split

#### Source vs Destination Port

- Destination port → routes traffic to the correct service on the target
- Source port (ephemeral) → routes the reply back to the correct requesting program on the origin host

#### TCP Reliability

- Built around acknowledgments — confirms data received, avoids wasted retransmission
- Checksum recalculated on receipt and compared to header value to catch loss/corruption

### TCP Control Flags & Connection Handshakes

TCP establishes connections for long chains of segments — unlike IP/Ethernet, which send individual packets independently.

#### The Six TCP Control Flags

|Flag|Meaning|Function|
|---|---|---|
|URG|Urgent|Segment is urgent; examine the urgent pointer field. Rarely adopted in practice|
|ACK|Acknowledged|Acknowledgment number field should be examined|
|PSH|Push|Sender wants buffered data pushed to the receiving application immediately|
|RST|Reset|One side can't recover from missing/malformed segments; restart from scratch|
|SYN|Synchronize|Used when establishing a connection; tells receiver to examine the sequence number field|
|FIN|Finish|Sender has no more data; connection can be closed|

#### Buffering & PSH

- Buffer = holding data before sending it on, for more efficient delivery of meaningful chunks
- PSH overrides this when a small amount of data needs immediate delivery to the listening program

#### Three-Way Handshake (Connection Establishment)

1. **Computer A → B:** SYN set — "let's connect, here's my sequence number"
2. **Computer B → A:** SYN + ACK set — "agreed, I acknowledge your sequence number"
3. **Computer A → B:** ACK set — "I acknowledge your acknowledgment, sending data now"

- After completion, connection operates in **full duplex**
- Every segment sent should be answered with an ACK

#### Four-Way Handshake (Connection Termination)

1. Side ready to close sends **FIN**
2. Other side responds **ACK**
3. Other side sends its own **FIN** (when ready to close too)
4. First side responds **ACK**

- A connection can theoretically stay open in simplex mode with only one side closed, but this is uncommon in practice

### TCP Sockets & Connection-Oriented vs Connectionless Protocols

#### Sockets

- A **socket** = the instantiation of an endpoint in a potential TCP connection (requires an actual program)
- A **port** = virtual/descriptive only; traffic can be sent to any port, but only gets a response if a program has opened a socket there
- Socket state definitions/names vary by OS — check the specific system when troubleshooting

#### TCP Socket States

|State|Meaning|Seen on|
|---|---|---|
|LISTEN|Socket ready for incoming connections|Server only|
|SYN_SENT|Sync request sent, connection not yet established|Client only|
|SYN_RECEIVED|Received SYN, sent SYN/ACK, awaiting final ACK|Server only|
|ESTABLISHED|Connection working, both sides can send data|Client & server|
|FIN_WAIT|FIN sent, awaiting corresponding ACK|Client & server|
|CLOSE_WAIT|Closed at TCP layer, but app hasn't released the socket|Client & server|
|CLOSED|Fully terminated, no further communication|Client & server|

#### Connection-Oriented Protocols (TCP)

- Establishes a connection; every segment sent is acknowledged
- Both ends always know what's been delivered vs. not
- Protects against: line errors, congestion drops, physical link failures, etc.
- Lower layers (IP/Ethernet) use checksums but **discard** bad data with no resend — resending is TCP's job
- Sequence numbers let out-of-order segments be reassembled correctly
- Tradeoff: connection setup + constant ACKs + teardown = significant overhead

#### Connectionless Protocols (UDP)

- **UDP** (User Datagram Protocol) — no connection, no acknowledgments
- Just set a destination port and send
- Best for data where some loss is acceptable (e.g. streaming video — losing a few frames is fine)
- Lower overhead than TCP → more bandwidth available for actual data

### System Ports vs Ephemeral Ports

Ports (16-bit numbers) direct traffic to specific services. TCP segments activate a listening port into a **socket**.

#### Ports and Sockets

- Port = number identifying where to direct traffic
- Socket = an active port a service is listening on
- Service/server = program waiting to respond to requests
- Client = program requesting data

#### Three Port Categories (IANA)

|Category|Range|Use|
|---|---|---|
|System Ports|1–1023|Reserved for common apps (FTP=21, Telnet over TLS/SSL=992). Many unassigned. Not used for outbound traffic on modern OSes|
|User Ports|1024–49151|Registered by vendors for specific server apps; not all officially registered with IANA|
|Ephemeral (Dynamic/Private) Ports|49152–65535|Temporary, client-side only, used for private transfers|

- 65,535 total possible ports (16-bit number)
- Not all OSes strictly follow IANA recommendations — IANA registry is still the most reliable reference
- References: [IANA port registry](https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.xhtml), [common ports list (PDF)](https://packetlife.net/media/library/23/common_ports.pdf)

#### Data Integrity

- TCP segment carries acknowledgments (confirms data received) + checksum verification (confirms received data matches sent data)

#### Port Security

- Ports can also be an entry point for malware
- Malicious actors use port scanning to find open/unsecured ports or weak points
- Mitigation: firewall to secure ports, only open sockets as needed

### Firewalls

A firewall blocks traffic that meets defined criteria. Primary tool for keeping unwanted traffic out of a network.

#### Where Firewalls Operate

- Can operate at multiple layers: application layer (deep inspection) or based on IP ranges
- Most commonly discussed here at the **transport layer**
- Transport-layer firewalls filter based on **ports** — block/allow specific port ranges

#### Example: Small Business Network

- One server hosting multiple services (web server + internal file server on the same box)
- Perimeter firewall config:
    - Allow external traffic to **port 80** (public webpage access)
    - Block external access to **all other ports** (keeps file server private to the LAN)

#### Firewall Deployment

- Not always a standalone device — really just a program that can run anywhere
- Home/many business setups: router + firewall functionality combined in one device
- Can also run on individual hosts (host-based firewall)
- Built into all major modern OSes — enables per-host control over port/service access
