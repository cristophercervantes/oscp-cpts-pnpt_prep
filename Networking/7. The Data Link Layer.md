# Ethernet and MAC Addresses

## What Ethernet does

Ethernet is the protocol most widely used to send data across individual network links. It operates at the data link layer (Layer 2) and abstracts away the physical layer — higher layers like transport and application don't need to know whether the device is using twisted pair cable, fiber, or wireless. Ethernet handles that for them.

Ethernet has been around since 1980 and largely unchanged in its core design since 1983.

## The collision domain problem

Before switches existed, all devices on a network shared a single collision domain — if two devices sent data at the same time, the electrical signals collided and both transmissions were corrupted. Everything had to be retransmitted.

Ethernet solved this with **CSMA/CD — Carrier Sense Multiple Access with Collision Detection**.

How it works:

1. A device checks if the channel is clear before sending
2. If two devices transmit simultaneously and a collision occurs, both detect it and stop
3. Each waits a random interval before retrying — the random delay prevents them from colliding again immediately

## MAC addresses — identifying devices on a network

When all devices receive all traffic on a shared segment, there needs to be a way to identify who the data is actually for. This is what **MAC (Media Access Control) addresses** do.

A MAC address is a globally unique 48-bit identifier assigned to every network interface. It's written as six groups of two hexadecimal digits:

Example: `00:1A:2B:3C:4D:5E`

**Hexadecimal** uses 16 digits (0–9 and A–F, where A=10, B=11, C=12, D=13, E=14, F=15). Each pair of hex digits is called an **octet** and represents 8 bits.

Total possible MAC addresses: 2⁴⁸ = 281 trillion+ — enough to be globally unique.

## MAC address structure

|Portion|Octets|Assigned by|
|---|---|---|
|OUI (Organizationally Unique Identifier)|First 3 octets|IEEE — identifies the manufacturer|
|Device identifier|Last 3 octets|Manufacturer — must be unique per device|

Knowing the OUI means you can identify the manufacturer of any network interface just from its MAC address.

Every Ethernet transmission includes both the sender's MAC address and the intended recipient's MAC address — this is how devices on a shared segment know whether traffic is meant for them.

# Unicast, Multicast, and Broadcast

## Three types of Ethernet transmission

### Unicast

One device sending to one specific device. The least significant bit of the first octet in the destination MAC address is set to **0**. The frame is sent to all devices on the collision domain but only the intended recipient processes it.

### Multicast

Sent to all devices on the local network segment, but each device decides whether to accept or discard it based on preconfigured multicast address lists — not just its own MAC address. The least significant bit of the first octet in the destination MAC address is set to **1**.

### Broadcast

Sent to every device on the LAN. Uses the special broadcast address: `FF:FF:FF:FF:FF:FF` (all Fs). Used so devices can learn about each other on the network.

# Ethernet Frames

## What an Ethernet frame is

A **data packet** is any single set of binary data sent across a network link. At the Ethernet level, data packets are called **Ethernet frames** — a highly structured collection of information in a specific order that allows network interfaces to convert raw bits into meaningful data.

## Structure of an Ethernet frame

### 1. Preamble (8 bytes / 64 bits)

Split into two parts:

- **First 7 bytes** — alternating 1s and 0s. Acts as a buffer between frames and helps network interfaces synchronize their internal clocks.
- **Last byte — SFD (Start Frame Delimiter)** — signals that the preamble is over and the actual frame content follows.

### 2. Destination MAC address (6 bytes / 48 bits)

The hardware address of the intended recipient.

### 3. Source MAC address (6 bytes / 48 bits)

The hardware address of where the frame originated.

### 4. EtherType field (2 bytes / 16 bits)

Describes the protocol of the frame's contents (e.g. IPv4, IPv6, ARP).

**OR — VLAN header** (if present, comes before EtherType) Indicates a VLAN frame. A VLAN (Virtual LAN) allows multiple logical networks to operate on the same physical equipment. Frames with a VLAN tag are only delivered out of switch interfaces configured for that tag. Commonly used to separate traffic types — e.g. IP phones on one VLAN, desktops on another.

### 5. Payload (46–1500 bytes)

The actual data being transported — everything from higher layers (IP, transport, application). This is the content, not the headers.

### 6. Frame Check Sequence / FCS (4 bytes / 32 bits)

A checksum used to verify data integrity, calculated using a **CRC (Cyclic Redundancy Check)**.

## How CRC works

1. The sending device collects all frame data and performs a CRC calculation, producing a checksum number
2. That checksum is attached as the FCS at the end of the frame
3. The receiving device performs the same CRC calculation on the received data
4. If the checksums match — data arrived intact
5. If they don't match — data was corrupted or lost in transit, and the frame is discarded

**Important:** Ethernet only detects data integrity issues. It does not recover or retransmit data. That responsibility belongs to higher-layer protocols (e.g. TCP).
## Ethernet frame at a glance

```
| Preamble (8B) | Dest MAC (6B) | Src MAC (6B) | EtherType (2B) | Payload (46-1500B) | FCS (4B) |
```
