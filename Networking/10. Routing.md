# Routing Basics

A router is a network device that forwards traffic based on the destination IP address. It must have at least two network interfaces since it connects two or more networks.

## The four steps of basic routing

1. Router receives a packet on one of its interfaces
2. Router examines the destination IP address
3. Router looks up the destination network in its routing table
4. Router forwards the packet out through the interface closest to the destination network

These steps repeat at every router along the path until the packet reaches its destination.

## How it works 

**Setup:**

- Network A: `192.168.1.0/24` — router interface at `192.168.1.1`
- Network B: `10.0.0.0/24` — router interface at `10.0.0.254`

**Process (computer at `192.168.1.100` sends data to `10.0.0.10`):**

1. The computer knows `10.0.0.10` is not on its local subnet
2. It sends the packet to its gateway's MAC address (the router)
3. The router receives the packet, strips the Ethernet frame (data link layer), and examines the IP datagram
4. It finds destination IP `10.0.0.10`, looks up its routing table, and identifies Network B as the correct path — directly connected
5. The router decrements the TTL field by 1 and recalculates the checksum
6. It builds a new Ethernet frame with its Network B interface as the source MAC and `10.0.0.10`'s MAC (from its ARP table) as the destination
7. Packet is sent out the Network B interface and delivered

## Three network example

Add Network C: `172.16.1.0/23`, connected to Network B via a second router.

Computer at `192.168.1.100` wants to reach `172.16.1.100`:

1. Packet goes to first router (A↔B gateway)
2. Router checks routing table — knows Network C is reachable via another router at `10.0.0.1`
3. Decrements TTL, forwards to `10.0.0.1`
4. Second router receives it, sees `172.16.1.100` is directly connected, delivers it

## At internet scale

The same process — just more routers and more hops. A packet may cross dozens of routers before reaching its destination.

Core internet routers are connected in a **mesh** — multiple possible paths exist between any two points. This provides resilience if one path goes down. Routers always choose the fastest/most efficient available path via their routing tables.


**Routing table** — a list of known networks and the best interface or next-hop router to reach them. Every router maintains one.

**Gateway** — a router's interface on a local network that local devices send traffic to when the destination is outside the local subnet.

**TTL decrement** — every time a packet passes through a router, the TTL field is decremented by 1. When it hits 0, the packet is dropped. This prevents infinite routing loops.

**Re-encapsulation** — at each hop, the router strips the old Ethernet frame and creates a new one with updated source and destination MAC addresses. The IP datagram inside is preserved (minus TTL and checksum update).

# 76 - Routing Tables

A routing table is a list of known networks and the information needed to forward traffic toward each one. Every router (and every major operating system) maintains one. Early routers were just regular computers with two network interfaces and a manually updated routing table — you could still build one that way today.

## The four columns of a routing table

### 1. Destination Network

Defines each network the router knows about — the network ID and subnet mask (often written in CIDR notation). When a packet arrives, the router examines the destination IP and matches it against entries in this column to find which network it belongs to.

A routing table always has a **catch-all entry** that matches any IP address not explicitly listed — traffic with no matching entry gets forwarded there (typically toward the internet gateway).

### 2. Next Hop

The IP address of the next router that traffic should be sent to in order to reach the destination network. If the network is directly connected, this column indicates no additional hops are needed.

### 3. Total Hops

How many router hops away the destination currently is. This is how routers choose between multiple possible paths to the same destination — they prefer the shortest path.

The "best path" can change over time: routers go down, links disconnect, new routers appear, or congestion slows certain routes. Routers track hop counts so that when they receive updated information from neighbors, they know whether a better path has become available.

### 4. Interface

Which of the router's own network interfaces to send traffic out of when forwarding to a given destination network.

## Scale

For a home or small office router, the routing table is simple — just a handful of entries. Core internet routers maintain **millions of rows** in their routing tables, and every single packet that passes through must be matched against the table before being forwarded. The process happens constantly, at enormous speed, for all traffic on the internet.

# Routing Protocols
## What routing protocols do

Routers use routing protocols to share information with each other about the networks they know and the best paths to reach them. This is how a router can learn the best path to a network on the other side of the planet.

## Two categories of routing protocols

**Interior Gateway Protocols (IGP)** — used by routers to share information _within_ a single autonomous system.

**Exterior Gateway Protocols (EGP)** — used for exchanging information _between_ independent autonomous systems. (BGP is the primary example, used by ISPs to communicate across the internet.)

**Autonomous system** — a collection of networks all under the control of a single network operator. Examples: a large corporation's internal network, or a national ISP's network.

## Two types of Interior Gateway Protocols

### Distance Vector Protocols (older)

A router shares its routing table — a list of every known network and how many hops away each one is — with every directly connected neighboring router.

**How it works:**

- Router A thinks Network X is 4 hops away via Router C
- Router B knows Network X is only 2 hops away, and sends its routing table to Router A
- Router A calculates: even with the extra hop to reach Router B, Network X is now only 3 hops away via Router B
- Router A updates its table accordingly

**Limitation:** Routers only know what their immediate neighbors tell them. They have limited visibility into the broader network state and can be slow to react to distant changes.

The term "distance vector" comes from the fact that in computer science, a list is called a vector — so this protocol sends a list (vector) of distances to networks.

### Link State Protocols (modern)

Each router advertises the state of each of its own interfaces (whether connected to another router or directly to a network) to every other router in the autonomous system.

**How it works:**

- Every router knows the full topology of the entire autonomous system — not just its neighbors
- Each router runs algorithms against this complete picture to calculate the best path to every destination network
- Routing tables are updated based on that calculation

**Trade-off:** Requires more memory (to store the full network state) and more processing power (to run the path-finding algorithms). As hardware has become cheaper and more powerful, link state protocols have largely replaced distance vector protocols.

# Exterior Gateway Protocols and ASNs

Interior gateway protocols share routing information within a single autonomous system (one organization). Exterior gateway protocols (EGPs) share routing information between different autonomous systems — between different organizations.

EGPs are fundamental to how the internet works. The internet is a massive mesh of autonomous systems, and core internet routers need to know how to route traffic between them.

The primary goal of a core internet router is to get data to the **edge router of the correct autonomous system**. Everything inside that autonomous system is handled internally from there.
## IANA — Internet Assigned Numbers Authority

A non-profit organization responsible for:

- **IP address allocation** — without a single authority managing this, anyone could claim any IP space they wanted, causing total chaos
- **ASN (Autonomous System Number) allocation** — assigns unique numbers to autonomous systems
## ASNs — Autonomous System Numbers

An ASN is a unique identifier assigned to an autonomous system. Like IP addresses, they are 32-bit numbers — but unlike IP addresses, they are written as a single decimal number rather than split into octets.

Two reasons for the difference in format:

1. **IP addresses** need to represent both a network ID and host ID, which is more readable when split into four octets. **ASNs** never need to be subdivided — the routing table just needs to map an ASN to the networks it represents.
    
2. **ASNs are looked at by humans far less frequently** than IP addresses. Knowing that ASN 19604 belongs to IBM is enough for practical purposes — there's no need for the octect format.
    

## How core internet routing works

Core internet routers maintain routing tables that map ASNs to their edge routers. When traffic is destined for an IP address, the core router identifies which autonomous system owns that IP space, routes the packet to the edge of that autonomous system, and leaves internal delivery to the AS's own routing.

# Non-Routable Address Space and RFC 1918
## The IPv4 exhaustion problem

IPv4 uses 32-bit addresses — a maximum of 4,294,967,295 unique addresses. As of 2017, there were an estimated 7.5 billion humans on earth, plus countless servers, data centers, and connected devices. IPv4 simply doesn't have enough addresses for everyone and everything that needs one.

This problem was recognized as early as 1996.

## RFC 1918 — non-routable address space

**RFC** stands for _Request for Comments_ — the longstanding mechanism by which the people responsible for running the internet agree on standards.

In 1996, RFC 1918 defined ranges of IP addresses designated as **non-routable address space**. These address ranges:

- Can be used by anyone for internal networks
- Will never be forwarded by core internet routers (exterior gateway protocols ignore them)
- Can be routed internally within an autonomous system (interior gateway protocols will route them)
- Belong to no one — free to use for private networks

Because they are completely separated from public internet routing, there is no conflict if many different organizations use the same private address ranges internally — they never meet on the public internet.

## The three RFC 1918 private ranges

|Range|CIDR|Notes|
|---|---|---|
|`10.0.0.0`|/8|~16.7 million addresses|
|`172.16.0.0`|/12|~1 million addresses|
|`192.168.0.0`|/16|~65,000 addresses|

`192.168.x.x` is the range you most commonly see on home networks.

## The limitation 

Devices on non-routable address space cannot directly communicate with the public internet. A technology called **NAT (Network Address Translation)** solves this by allowing devices on private address space to reach external internet addresses through a router with a single public IP. This is covered in a later module.

# RFCs and Internet Standards

**RFC** stands for _Request for Comments_. RFCs started as a way for academics to discuss how their computers could talk to each other. The process: publish a document, collect comments, build consensus, develop a standard.

Over decades, RFCs have become the primary mechanism by which internet standards are created and maintained.

## The IETF

RFCs now belong to the **IETF — Internet Engineering Task Force**, an open community responsible for developing and maintaining the standards that keep the internet running.

The full collection of RFCs is publicly available at [ietf.org/standards/rfcs](https://www.ietf.org/standards/rfcs/).
