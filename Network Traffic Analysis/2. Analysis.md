## Traffic Analysis 

Network Traffic Analysis (NTA) is a dynamic, structured process used to examine network communications, isolate operational anomalies, and detect malicious behavior (such as unauthorized remote access via RDP, SSH, or Telnet). By evaluating trends against an established network baseline, security analysts and administrators gain essential visibility to troubleshoot connectivity issues and accelerate incident response.

## Active vs. Passive Traffic Capture

Capturing network traffic depends on key operational and structural requirements:

|Dependency|Passive Capture|Active Capture|Description|
|---|---|---|---|
|**Written Permission**|**Yes**|**Yes**|Explicit written authorization is required to ensure compliance with organization policy and legal standards (e.g., healthcare, finance).|
|**Port Mirroring (SPAN)**|**Yes**|No|Switches/routers copy traffic to a designated port; requires placing the NIC into promiscuous mode.|
|**In-Line Placement / Taps**|No|**Yes**|Requires topology changes to place hardware TAPs or multi-NIC hosts directly in-line between network segments (ideally Layer 3 links).|
|**Capture Tools**|**Yes**|**Yes**|Ingests traffic using software like `tcpdump`, Wireshark, or Netminer.|
|**High Storage & CPU Power**|**Yes**|**Yes**|Higher resource allocation is required for active/routed captures due to heavy traffic volume.|

 **Operational Insight**: While passive capture acts like filling a cup from a water fountain, active capture on routed links functions like a high-pressure firehose, requiring significant processing power and storage capacity.

## The Analysis Workflow

```
[Descriptive Analysis] -> [Diagnostic Analysis] -> [Predictive Analysis] -> [Prescriptive Analysis]
```

### 1. Descriptive Analysis (Scope & Objectives)

Establishes what event occurred, sets boundaries, and identifies investigation targets.

- **Goal**: Identify scope, problem type, target subnets, timeframe, and target protocols (e.g., inspecting `192.168.100.0/24` for HTTP/FTP downloads of `superbad.exe` over a 48-hour window).
    

### 2. Diagnostic Analysis (Root Cause & Filtering)

Examines historical/live data to establish direct causes and connections.

- **Goal**: Filter out known-good baseline traffic to isolate anomalies.
    
- **Execution**: Reconstruct transferred files via `ftp-data` or isolate HTTP requests with display filters like `http.request.method == "GET"`.
    

### 3. Predictive Analysis (Trend & Threat Evaluation)

Applies findings to identify ongoing threats, systemic risk, and potential escalation.

- **Goal**: Document findings using precise mind maps, timestamps, packet numbers, and host profiles to predict threat progression and outline impact.
    

### 4. Prescriptive Analysis (Remediation & Lessons Learned)

Determines precise corrective actions to resolve the immediate threat and prevent recurrences.

- **Goal**: Execute response actions (e.g., host isolation, rule updates) and document lessons learned to strengthen future workflows.
    

## Practical Analysis Tactics & Threat Indicators

- **Host-to-Host Internal Traffic**: User workstations rarely communicate directly with one another. Direct host-to-host traffic over management or sharing ports (e.g., `445` SMB or `8080` HTTP) is highly suspicious and warrants immediate investigation.
    
- **C2 Beacons & Regular Intervals**: Look for automated, regular connection intervals from internal assets reaching out to external IP addresses.
    
- **Protocol Prioritization**: Start analysis with high-volume perimeter protocols (HTTP/S, FTP, Email), moving inward to remote administration protocols (SSH, RDP, Telnet).
    
- **Anomalous Behavioral Outliers**: Monitor for abnormal User-Agent strings, uncommon single-use port bindings, or drastic changes in host activity patterns.
