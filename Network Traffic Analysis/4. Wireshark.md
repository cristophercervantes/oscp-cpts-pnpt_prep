## What Wireshark is

Wireshark is a free, open-source network traffic analyzer with a graphical interface. It supports deep packet inspection for hundreds of protocols, can capture live traffic from many interface types (Ethernet, Wi-Fi, Bluetooth, USB), and can decrypt traffic for IPsec, TLS, WPA/WPA2, and more.

## TShark — basic commands

```bash
# Find TShark
which tshark

# Install on Linux
sudo apt install wireshark

# List available interfaces
tshark -D

# List link-layer mediums
tshark -L

# Capture on an interface and save to file
sudo tshark -i eth0 -w /tmp/test.pcap

# Read from a saved capture file
tshark -r /tmp/test.pcap

# Apply a capture filter (BPF syntax)
sudo tshark -i eth0 -f "host 172.16.146.2"

# Print packet summaries while writing to file
sudo tshark -i eth0 -w /tmp/test.pcap -P

# Add hex and ASCII output
tshark -r file.pcap -x

# Help
tshark -h
```

### TShark switch reference

|Switch|What it does|
|---|---|
|`-D`|List available capture interfaces, then exit|
|`-L`|List link-layer mediums, then exit|
|`-i`|Choose interface to capture from (e.g. `-i eth0`)|
|`-f`|Capture filter in BPF syntax|
|`-c`|Capture a specific number of packets then stop|
|`-a`|Autostop condition (duration, file size, or packet count)|
|`-r`|Read from a pcap file|
|`-W`|Write output to a pcapng file|
|`-P`|Print packet summary while writing to file|
|`-x`|Add hex and ASCII output|
|`-h`|Show help|

## Termshark

A TUI (Text-based User Interface) application that provides a Wireshark-like interface inside the terminal. Useful when you need the Wireshark layout but have no desktop environment.

Install: download from `https://github.com/gcla/termshark/releases`

Start it the same way as TShark — specify interface and filters from the terminal. The window won't open until it detects traffic matching the capture filter.

## Wireshark GUI — three panes

**Packet List (top)** — one line per packet showing: packet number, time, source IP, destination IP, protocol, and info. Columns are customizable.

**Packet Details (middle)** — expands the selected packet layer by layer following the OSI model. Wireshark displays encapsulation in reverse — lower layers at the top, higher layers at the bottom (the order they were unencapsulated).

**Packet Bytes (bottom)** — raw packet content in hex and ASCII. Selecting a field in the Details pane highlights the corresponding bytes here. Each line shows the offset, 16 hex bytes, and 16 ASCII bytes. Non-printable characters show as periods.

## Starting a capture in Wireshark

1. Open Wireshark
2. Click the **Capture** menu → select the interface to capture on
3. Optionally set a capture filter before starting
4. Click **Start**

To save: File → Save, or use the toolbar. Wireshark supports multiple file formats — `.pcap` is the standard.

Note: changing capture options while running will restart the trace.

## Capture filters vs display filters

**Capture filters** — applied before the capture starts. Use BPF syntax. Traffic not matching the filter is dropped entirely and not saved to the file. Fewer filter options but reduces disk usage.

**Display filters** — applied during or after capture. Proprietary Wireshark syntax. Traffic is still captured and saved — the filter only changes what is shown. More powerful and flexible.

### Capture filter reference (BPF syntax)

|Filter|Result|
|---|---|
|`host x.x.x.x`|Only traffic to/from a specific host|
|`net x.x.x.x/24`|Traffic to/from a specific network|
|`src net x.x.x.x/24`|Traffic sourcing from a specific network|
|`dst net x.x.x.x/24`|Traffic destined to a specific network|
|`port 80`|Only port 80 traffic|
|`not port 80`|Everything except port 80|
|`port 80 and 443`|Both ports|
|`portrange 1000-2000`|Traffic on any port in the range|
|`ip / tcp / ether`|Only the specified protocol|
|`broadcast / multicast / unicast`|Filter by traffic type|

### Display filter reference (Wireshark syntax)

|Filter|Result|
|---|---|
|`ip.addr == x.x.x.x`|Traffic involving a host (OR — either src or dst)|
|`ip.addr == x.x.x.x/24`|Traffic involving a network|
|`ip.src == x.x.x.x`|Traffic from a specific source|
|`ip.dst == x.x.x.x`|Traffic to a specific destination|
|`dns / tcp / ftp / arp / ip`|Filter by protocol|
|`tcp.port == 443`|Filter by specific TCP port|
|`tcp.port != 80`|Everything except port 80|
|`and / or / not`|Combine filters|


Filtering for port 80 is not the same as filtering for HTTP. Port filters show everything using that port regardless of application protocol. Protocol filters (like `http`) look for specific protocol markers (GET/POST requests, etc.). Use the one that matches what you actually need.

## Applying filters in Wireshark

**Capture filter:** Capture menu → Options → enter filter in "Capture filter for selected interfaces" field → Start

**Display filter:** Type directly into the filter bar at the top of the capture window. If the field turns green, the filter syntax is valid.

### Wireshark Advanced Usage

Advanced Wireshark features: Statistics/Analyze plugins, TCP stream following, file extraction from captures.

#### Statistics Tab

Provides conversation metadata and protocol breakdowns for the entire PCAP.

- Top talkers, protocol hierarchy, conversations by IP/protocol
- Access: **Statistics** menu

#### Analyze Tab

Provides filtering, stream-following, and traffic diagnostics tools.

- Prepare/apply display filters
- Follow TCP/UDP/SCTP streams
- Conversation filters
- Expert Information (Wireshark-generated diagnostics)
- Access: **Analyze** menu

#### Following TCP Streams

Reconstructs a full TCP conversation into readable form; can pull out images, files, etc. Works for any TCP-based protocol.

**Via GUI:**

- Right-click a packet in the stream → **Follow → TCP**
- Opens a new window with the stitched-together conversation

**Via filter:**

```
tcp.stream eq #
```

#### Extracting Files From a Capture

Requires the full conversation to be captured — incomplete captures fail to reassemble.

Steps (GUI):

1. Stop the capture
2. **File → Export →** select protocol format (DICOM, HTTP, SMB, etc.)

#### FTP Traffic Analysis

FTP uses TCP, ports 20 (data) and 21 (control/commands: login, list, upload/download).

|Filter|Shows|
|---|---|
|`ftp`|All FTP protocol traffic|
|`ftp.request.command`|Commands sent over control channel (port 21) — usernames, passwords, filenames|
|`ftp-data`|Data transferred over data channel (port 20)|

**Extracting an FTP file — workflow:**

1. Identify FTP traffic with `ftp` filter
2. Check `ftp.request.command` to see what was transferred and by whom
3. Filter `ftp-data`, select the packet for the file of interest, **Follow TCP Stream**
4. Set "Show and save data as" → **Raw**, save with original filename
5. Validate extraction by checking file type
