## Overview of Tcpdump

`tcpdump` is a command-line packet analyzer for Unix-like systems (with a deprecated Windows port named WinDump). It captures and decodes network frames using `pcap`/`libpcap` libraries while relying on standard interface promiscuous modes to process local network traffic.

### System Requirements & Capabilities

- **Privileges**: Requires `root` or `sudo` administrative rights to access raw network sockets and hardware interfaces directly.
    
- **No GUI Required**: Operates strictly via terminal or remote SSH sessions.
    
- **Pre-requisites**: Can be validated using `which tcpdump` or installed via `sudo apt install tcpdump`.
    

## Basic Command Switches

| Switch              | Usage / Result                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------ |
| `-D`                | Lists all network interfaces available for packet capture.<br><br>                         |
| `-i <interface>`    | Directs `tcpdump` to capture traffic from a specified interface (e.g., `-i eth0`).<br><br> |
| `-nn`               | Disables name resolution for both hostnames (IPs) and port numbers.<br><br>                |
| `-e`                | Includes Link-Layer (Ethernet) headers in the output stream.<br><br>                       |
| `-X`                | Displays packet content in both Hexadecimal and ASCII representation.<br><br>              |
| `-XX`               | Displays Hexadecimal and ASCII output including the Link-Layer/Ethernet header.<br><br>    |
| `-v`, `-vv`, `-vvv` | Increases output verbosity (shows IP TTL, ID, options, length, and checksums).<br><br>     |
| `-c <count>`        | Captures a specified number of packets and automatically exits.<br><br>                    |
| `-S`                | Converts relative sequence numbers to absolute sequence numbers.<br><br>                   |
| `-q`                | Quiet output; prints less protocol header detail.<br><br>                                  |
| `-w <file.pcap>`    | Directs captured raw frames to a PCAP output file.<br><br>                                 |
| `-r <file.pcap>`    | Reads and parses captured packets directly from an existing PCAP file.<br><br>             |

## Output Header Breakdown

When examining a live capture stream or reading from a file, a standard output line follows a distinct structure:

```
17:39:26.500472 IP 172.16.146.2.21 > 172.16.146.1.49769: Flags [P.], seq 1:77, ack 17, win 509, options [...], length 76
```

1. **Timestamp**: Configurable timestamp indicating the capture time of the packet frame.
    
2. **Protocol**: Shows the transport/network protocol (e.g., `IP`).
    
3. **Source & Destination**: Formatted as `Source_IP.Port > Destination_IP.Port`.
    
4. **Flags**: Displays TCP flags (`[S]` Syn, `[P.]` Push-Ack, `[F.]` Fin-Ack, `[.]` Ack).
    
5. **Sequence & Ack Numbers**: Tracks segment bytes (`seq 1:77`, `ack 17`).
    
6. **Protocol Options / Window**: Details negotiated parameters like TCP window size (`win 509`) and timestamps.
    
7. **Length & Dissector Notes**: Shows payload byte length alongside protocol disclosures (e.g., `FTP: 220 Welcome...`).
    

## Usage Examples

### Listing Available Interfaces

```
sudo tcpdump -D
```

Identifies available adapters such as `eth0`, `any`, or `lo`.

### Capturing with No Name Resolution & Verbose Output

```
sudo tcpdump -i eth0 -nnvXX
```

Captures on `eth0`, keeping IP/port numbers numerical, with high verbosity and full Hex/ASCII payload + Ethernet header display.

### Reading and Writing PCAP Files

```
# Write traffic to a file
sudo tcpdump -i eth0 -w ~/capture.pcap

# Read traffic from a file
sudo tcpdump -r ~/capture.pcap -nn
```

Stores traffic directly into a PCAP file without printing standard terminal output, then reads the stored output back with name resolution turned off.

##  Tcpdump Filters

|**Filter**|**Description**|
|---|---|
|**`host`**|Filters traffic associated with a designated IP address (bi-directional).|
|**`src` / `dst`**|Modifiers to specify the source or destination host, network, or port.|
|**`net`**|Filters traffic to or from a specific network range using CIDR notation (e.g., `172.16.146.0/24`).|
|**`proto`**|Filters for specific protocol types by name or protocol number (e.g., `tcp`, `udp`, `icmp` or protocol `17`).|
|**`port` / `portrange`**|Filters for a specific port or a range of ports (e.g., `port 443`, `portrange 0-1024`).|
|**`less` / `greater`**|Filters packets based on total size in bytes (e.g., `greater 500` or `less 64`).|

## Logical Operators

- **`and` / `&&`**: Combines multiple criteria (e.g., `host 192.168.0.1 and port 23`).
    
- **`or` / `||`**: Matches packets meeting either condition (e.g., `icmp or host 172.16.146.1`).
    
- **`not` / `!`**: Negates a condition to exclude specific traffic (e.g., `not icmp`).
    

## Command Line Switches & Advanced Filtering

- **`-A`**: Displays output in ASCII text for quick human readability.
    
- **`-l`**: Line-buffers output so it can be piped directly into utilities like `grep` (e.g., `tcpdump -Ar http.cap -l | grep 'mailto:*'`).
    
- **`-S`**: Displays absolute TCP sequence numbers instead of relative ones.
    
- **TCP Header Bitwise Inspection**: Filters specific TCP flags directly from the header bytes, such as capturing SYN packets via `'tcp[13] & 2 != 0'`.
