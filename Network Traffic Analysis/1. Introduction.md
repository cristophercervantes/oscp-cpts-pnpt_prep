## Network Traffic Analysis 

NTA is basically watching what's flowing through your network so you can spot what's normal, and catch what isn't. The core idea — any attacker who gets into your network _has_ to communicate with it. That communication leaves traces, and that's what you're hunting for.

### What NTA Is Used For

Catching threats in real time, building a picture of what "normal" looks like in your environment, spotting misconfigured or suspicious traffic, finding malware communicating on the wire, and going back through old captures during incident investigations.

A simple example — if you suddenly see a flood of SYN packets hitting ports that are never normally used, that's almost certainly a port scan. Knowing what's normal is what lets you spot that.

### What You Need to Know First

NTA isn't something you can do blind. You need a working understanding of the TCP/IP stack and OSI model, how packets are structured, common ports and protocols, and how TCP vs UDP behave differently. TCP is stream-based so you can follow full conversations. UDP is fire-and-forget, which makes reconstruction harder. Each layer wraps the one below it (encapsulation) — being able to read those headers speeds everything up.

### Tools

The main ones worth knowing: **Wireshark** is the GUI option, great for deep packet inspection. **tcpdump** is the command-line version, lightweight and scriptable. **TShark** is Wireshark's CLI variant. **NGrep** works like grep but for network packets — useful for HTTP/FTP debugging. **tcpick** specializes in reassembling TCP streams. On the infrastructure side, **network taps** and **span ports** let you copy traffic from a link without disrupting it. **SIEMs** like Splunk sit at the top, ingesting and visualizing everything.

Most of these share **BPF (Berkeley Packet Filter)** syntax for filtering — it's the common language across tools so worth learning once.

### The NTA Workflow

It's not a strict linear process, but it generally flows like this:

**1. Ingest** — get connected to the right network segment and start capturing. In switched environments you won't see traffic outside your broadcast domain, so placement matters. Span ports or taps solve this.

**2. Filter** — raw captures are noisy. Strip out broadcast and multicast traffic first to reduce the clutter before you start digging.

**3. Analyze** — start asking questions. Is traffic encrypted when it should be? Are hosts talking to each other that normally don't? Is anyone trying to reach resources they shouldn't have access to?

**4. Detect** — decide if what you're seeing is normal or suspicious. IDS/IPS tools can help here by running signatures against the capture automatically.

**5. Fix and Monitor** — not officially part of the loop but always should be. After making a change, keep watching to confirm the problem is actually gone.


## OSI and TCP/IP Models

The OSI and TCP/IP models serve as graphical representations of how network communication is handled between hosts. These models organize protocol functions into layered stacks to facilitate end-to-end data transfer and PDU management.

### Models

- **OSI Model**: A strict, theoretical seven-layer framework broken into granular functional chunks.
    
- **TCP/IP Model**: A loose, flexible four-layer model aligned directly with real-world network operational functionality.
    

### Model Traits Comparison

| Trait           | OSI Model                              | TCP/IP Model                                    |
| --------------- | -------------------------------------- | ----------------------------------------------- |
| **Layers**      | Seven<br><br>                          | Four<br><br>                                    |
| **Flexibility** | Strict<br><br>                         | Loose<br><br>                                   |
| **Dependency**  | Protocol independent & generic<br><br> | Based on common communication protocols<br><br> |

## Protocols, Layers, and PDUs

A Protocol Data Unit (PDU) is a data packet composed of control information and encapsulated data passed down through the network stack.

### Layer Breakdown & Mapping

| OSI Layer | OSI Layer Name | TCP/IP Layer          | PDU Name           | Typical Examples / Devices |
| --------- | -------------- | --------------------- | ------------------ | -------------------------- |
| **7**     | Application    | Application (Layer 4) | Data               | FTP, HTTP<br><br>          |
| **6**     | Presentation   | Application (Layer 4) | Data               | JPG, PNG, SSL, TLS<br><br> |
| **5**     | Session        | Application (Layer 4) | Data               | NetBIOS<br><br>            |
| **4**     | Transport      | Transport (Layer 3)   | Segment / Datagram | TCP, UDP<br><br>           |
| **3**     | Network        | Internet (Layer 2)    | Packet             | Router, L3 Switch<br><br>  |
| **2**     | Data-Link      | Link (Layer 1)        | Frame              | Switch, Bridge<br><br>     |
| **1**     | Physical       | Link (Layer 1)        | Bit                | Network Card<br><br>       |

### Encapsulation Mechanism

1. As higher-layer data moves down the stack, each layer wraps the upper-layer payload in a new bubble (encapsulation).
    
2. Layer-specific control information is added to the header (e.g., flags, options, IP addresses, ports, transport/application protocols).
    
3. Traffic analysis tools like Wireshark present PDUs in reverse order because captured data is unencapsulated bottom-up during analysis.
    

## Addressing Mechanisms

### 1. MAC Addressing (Layer 2 / Link)

- **Structure**: A 48-bit, 6-octet address represented in hexadecimal format.
    
- **Function**: Handles host-to-host delivery within a local broadcast domain.
    
- **Layer Crossing**: When crossing Layer 3 boundaries, the PDU is sent to the egress router interface. The router strips the Layer 2 header and replaces it with new Layer 2 addressing for the next physical hop.
    

### 2. IPv4 Addressing (Layer 3 / Internet)

- **Structure**: A 32-bit, 4-octet address represented in dotted-decimal format (each octet ranges from 0 to 255).
    
- **Function**: Provides primary global routing across different network boundaries.
    
- **Characteristics**: Connectionless protocol; does not guarantee packet delivery (relies on upper layers like TCP for reliability).
    

### 3. IPv6 Addressing (Layer 3 / Internet)

- **Structure**: A 128-bit, 16-octet address represented in hexadecimal format.
    
- **Purpose**: Solves IPv4 address exhaustion alongside VLSM and CIDR implementations.
    
- **Features**: Integrated IPSec security, simplified packet headers, global per-device addressing, and native multicast support.
    

#### IPv6 Addressing Types

| Type          | Description                                                                                                     |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| **Unicast**   | Addresses assigned to a single interface (host-to-host).<br><br>                                                |
| **Anycast**   | Addresses assigned to multiple interfaces where only one node receives the packet (one-to-one-of-many).<br><br> |
| **Multicast** | Addresses assigned to multiple interfaces where all nodes receive the packet (one-to-many).<br><br>             |
| **Broadcast** | Does not exist natively in IPv6; functionality is replaced using multicast addresses.<br><br>                   |

## Transport Layer Protocols (TCP vs. UDP)

The Transport Layer acts as a control hub, orchestrating encapsulation down the stack and reassembling incoming segments/datagrams in proper order.

### Characteristic Comparison

| Characteristic               | Transmission Control Protocol (TCP)                                     | User Datagram Protocol (UDP)                                   |
| ---------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Transmission**             | Connection-oriented<br><br>                                             | Connectionless ("fire and forget")<br><br>                     |
| **Connection Establishment** | Uses a 3-way handshake before transmitting data<br><br>                 | No handshake; does not check if recipient is listening<br><br> |
| **Data Delivery**            | Stream-based conversations<br><br>                                      | Packet-by-packet; ignores host destination state<br><br>       |
| **Receipt Verification**     | Sequence and Acknowledgement numbers track data delivery<br><br>        | No delivery receipt or receipt validation<br><br>              |
| **Speed & Overhead**         | Higher overhead and slower due to built-in validation functions<br><br> | Fast, low-overhead, but inherently unreliable<br><br>          |

## TCP Connection Lifecycle

### 1. TCP Three-Way Handshake

1. **SYN**: Client sends a TCP packet with the `SYN` flag enabled to synchronize sequence numbers and negotiate communication parameters (e.g., MSS, Window Size, SACK).
    
2. **SYN-ACK**: Server responds with a TCP packet containing both `SYN` (for sequence number agreement) and `ACK` (acknowledging client's `SYN`).
    
3. **ACK**: Client sends a final TCP packet with the `ACK` flag enabled to acknowledge the server's parameters, establishing the active connection.
    

### 2. TCP Session Teardown

To gracefully close an established TCP connection, hosts utilize the `FIN` (Finish) flag to signal completion of data transmission:

1. **FIN, ACK**: Sender requests termination after data delivery.
    
2. **FIN, ACK**: Receiver acknowledges termination request and sends its own `FIN`.
    
3. **ACK**: Sender responds with a final acknowledgment to close the connection.
    

## HTTP (Hypertext Transfer Protocol)

Hypertext Transfer Protocol (HTTP) is a stateless Application Layer protocol in use since 1990 that enables clear-text data transfer between a client and server over TCP. The client sends requests for resources, and the server responds with HTML, images, video, or hyperlinks.

### Specs

- **Standard Ports**: TCP 80 or 8000 (can be modified to use alternate ports or UDP in exceptional scenarios).
    
- **RFC Reference**: RFC 2616.

### HTTP Methods

|**Method**|**Type**|**Description**|
|---|---|---|
|**GET**|Required|Requests information and content from the server (e.g., `GET [http://10.1.1.1/Webserver/index.html](http://10.1.1.1/Webserver/index.html)`).|
|**HEAD**|Required|Similar to GET, but requests a response without the message body; used to check server operational status.|
|**POST**|Optional|Submits data to a server based on request fields; creates child entities at the provided URI.|
|**PUT**|Optional|Uploads data to create or update an object directly at the supplied URI.|
|**DELETE**|Optional|Removes the resource/object located at the specified URI.|
|**TRACE**|Optional|Echos back the received request for remote server diagnosis.|
|**OPTIONS**|Optional|Queries supported HTTP methods recognized by the server without requesting actual content.|
|**CONNECT**|Optional|Reserved for proxies/firewalls to establish tunnels over HTTP (e.g., SSL tunnels).|

**Note**: Standard HTTP implementations require `GET` and `HEAD` to be functional by default. All other methods are optional depending on server configuration (e.g., read-only sites).

## HTTPS (HTTP Secure)

HTTP Secure (HTTPS) is a modified implementation of HTTP designed to secure communications using Transport Layer Security (TLS) or legacy Secure Sockets Layer (SSL). TLS wraps the standard HTTP traffic to encrypt the entire session, mitigating Man-in-the-Middle (MitM) and hijacking attacks.

### Specs

- **Standard Ports**: TCP 443 or 8443.
    
- **RFC Reference**: RFC 2246.
    

### TLS Handshake Mechanism

1. **Hello Exchange**: Client and server exchange hello messages to agree on connection parameters.
    
2. **Cryptographic Exchange**: Key exchange occurs to establish a premaster secret.
    
3. **Authentication**: Exchange of x.509 certificates and cryptographic verification data.
    
4. **Master Secret Generation**: A 48-byte master secret is calculated from the premaster secret and shared random values.
    
5. **Record Layer Issue**: Negotiated security parameters are applied to the TLS Record Layer.
    
6. **Handshake Verification**: Both ends verify that security parameters match and confirm no tampering occurred.
    

## FTP (File Transfer Protocol)

File Transfer Protocol (FTP) is an Application Layer protocol used for transfer of data between network devices. FTP is inherently insecure (clear-text) and is widely replaced by protocols such as SFTP.

### Specs

- **Dual-Port Architecture**: Uses TCP port 21 for command/control and TCP port 20 for data transfer.
    
- **Authentication**: Supports standard user authentication as well as anonymous access.
    
- **RFC Reference**: RFC 959.
    

### Modes of Operation

- **Active Mode (Default)**: The server listens for a `PORT` command from the client specifying which port to use for the data transfer connection.
    
- **Passive Mode**: Used when clients are behind firewalls/NAT. The client issues a `PASV` command, and the server responds with an IP and port for the data connection.
    

### Common Control Commands

|**Command**|**Description**|
|---|---|
|**USER**|Specifies the username for login.|
|**PASS**|Submits the password for the authenticating user.|
|**PORT**|Sets the data port in active mode.|
|**PASV**|Toggles connection to passive mode.|
|**LIST**|Lists files in the current working directory.|
|**CWD**|Changes the current working directory.|
|**PWD**|Prints the current working directory path.|
|**SIZE**|Returns the file size in bytes.|
|**RETR**|Downloads/retrieves a file from the server.|
|**QUIT**|Terminates the control session.|

## SMB (Server Message Block)

Server Message Block (SMB) is a connection-oriented protocol widely used in Windows enterprise networks for sharing resources (files, printers, authentication) across hosts. It mandates user authentication to enforce access permissions.

### Specs

- **Modern Transport**: Direct TCP over port 445 (also supports QUIC and NetBIOS over TCP port 139).
    
- **Legacy Transport**: NetBIOS over UDP ports 137/138.
    

### Analysis & Traffic Indicators

- **Authentication Clusters**: Repeated login failures (e.g., `STATUS_LOGON_FAILURE`) inside SMB streams signal potential brute-force or credential abuse for lateral movement.
    
- **Unusual Access Patterns**: Direct file-share access host-to-host (rather than host-to-server) is abnormal and requires further investigation.
