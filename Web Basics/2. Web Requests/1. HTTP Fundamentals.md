## HyperText Transfer Protocol (HTTP)

HTTP is an application-level protocol used to access resources on the World Wide Web. It functions through a client-server model where a client (like a browser) requests a resource, and the server processes that request to return the desired data.

### URL Structure

Resources are accessed via a Uniform Resource Locator (URL). While only the **scheme** and **host** are mandatory, a full URL can contain several components:

|**Component**|**Example**|**Description**|
|---|---|---|
|**Scheme**|`https://`|Identifies the protocol (HTTP defaults to port 80, HTTPS to 443).|
|**User Info**|`admin:password@`|Optional credentials for authentication.|
|**Host**|`inlanefreight.com`|The location of the resource (Hostname or IP).|
|**Port**|`:80`|Specifies the specific port to connect to.|
|**Path**|`/dashboard.php`|Points to a specific file or folder.|
|**Query String**|`?login=true`|Parameters passed to the resource, starting with `?`.|
|**Fragment**|`#status`|Client-side pointer to a specific section of a page.|

### The HTTP Flow

When a user enters a URL, the following sequence occurs:

1. **DNS Resolution:** The browser contacts a DNS server to resolve the domain name into an IP address. Browsers check the local `/etc/hosts` file before contacting external DNS servers.
    
2. **Request:** Once the IP is known, the browser sends a request (usually a `GET` request) to the server.
    
3. **Processing:** The web server receives the request and identifies the resource (defaulting to `index.html` if no path is provided).
    
4. **Response:** The server returns the resource along with a status code (e.g., `200 OK`).
    
5. **Rendering:** The browser renders the HTML/CSS/JS for the user.
    

### Using cURL

`cURL` (Client URL) is a essential command-line tool for penetration testers to send web requests without a browser.

- **Basic Request:** `curl inlanefreight.com` displays the raw source code of the page.
    
- **Saving Output:**
    
    - `-O`: Saves the file using its remote name (e.g., `index.html`).
        
    - `-o [filename]`: Saves the output to a specific local filename.
        
- **Silent Mode:** `-s` hides the progress meter and status messages.
    
- **Help & Manual:** Use `-h` for basic options, `--help all` for detailed flags, or `man curl` for the full manual.

## HyperText Transfer Protocol Secure (HTTPS)

HTTPS is the secure version of HTTP, designed to provide encrypted communication between a client and a server. While standard HTTP transfers all data in clear-text, making it vulnerable to **Man-in-the-Middle (MiTM)** attacks, HTTPS ensures that intercepted data remains unreadable to third parties.

### HTTPS Overview

- **Encryption**: All communications are transferred in an encrypted format, protecting sensitive data like login credentials from being captured in plain text.
    
- **Identification**: Websites using HTTPS are identified by the `https://` scheme and a lock icon in the browser's address bar.
    
- **DNS Privacy**: Even with HTTPS, a visited URL might be revealed if using clear-text DNS; using encrypted DNS (like 8.8.8.8) or a VPN is recommended for full privacy.
    
### HTTPS Communication Flow

The transition from an unencrypted request to a secure connection involves several high-level steps:

1. **Redirection**: If a user attempts to connect via port 80 (HTTP), the server typically issues a `301 Moved Permanently` response to redirect the client to port 443 (HTTPS).
    
2. **Handshake Initiation**: The client sends a "client hello" with its information, and the server responds with a "server hello".
    
3. **Key Exchange**: The server and client exchange and verify SSL certificates to establish a secure channel.
    
4. **Encrypted Handshake**: A final handshake confirms that the encryption and data transfer are functioning correctly.
    
5. **Secure Communication**: Once confirmed, all subsequent HTTP communication is encrypted.
    

Attackers may attempt **HTTP downgrade attacks** using a MITM proxy to force traffic into clear-text, though most modern browsers and servers have built-in protections against this.

### Using cURL with HTTPS

cURL handles HTTPS handshakes and encryption automatically. However, security features may block connections under certain conditions:

- **Certificate Validation**: By default, cURL will refuse to connect to a site with an invalid or outdated SSL certificate to prevent MITM attacks.
    
- **Bypassing Checks**: During testing or when interacting with local lab environments that lack valid certificates, you can use the `-k` flag to tell cURL to skip certificate validation.
    
```
# Example of bypassing a certificate check
mubtasimfuad010101@host[/htb]$ curl -k https://www.inlanefreight.com
```

## HTTP Requests and Responses

Web communication is a conversation consisting of two parts: the **Request** (sent by the client) and the **Response** (sent by the server).

### The HTTP Request

Every request starts with a "Request Line" followed by headers and an optional body.

|**Field**|**Example**|**Description**|
|---|---|---|
|**Method**|`GET`|The action to perform (e.g., GET to retrieve, POST to send).|
|**Path**|`/users/login.html`|The specific resource being requested.|
|**Version**|`HTTP/1.1`|The protocol version being used.|

**Headers:** These are key-value pairs (like `Host: inlanefreight.com`) that provide metadata about the client, the preferred language, or session cookies.

**Body:** Contains data being sent to the server (common in POST requests for logins or file uploads).
### The HTTP Response

After processing the request, the server sends back a response.

1. **Status Line:** Contains the version and the **Status Code** (e.g., `HTTP/1.1 200 OK`).
    
2. **Headers:** Provide details about the server, the date, and the type of content being returned (e.g., `Content-Type: text/html`).
    
3. **Response Body:** The actual data requested, such as HTML code, an image, or a JSON object.
### Tools for Analysis

#### 1. cURL (Command Line)

To see the "behind the scenes" exchange that a browser usually hides, use the **verbose** flag:

- **`-v`**: Displays the full request (lines starting with `>`) and the full response (lines starting with `<`).
    
- **`-vvv`**: Provides even deeper technical details about the connection and handshake.
    
```
mubtasimfuad010101@htb[/htb]$ curl -v inlanefreight.com
> GET / HTTP/1.1
> Host: inlanefreight.com
...
< HTTP/1.1 200 OK
< Content-Type: text/html
```

#### 2. Browser DevTools

Every modern browser (Chrome, Firefox, Edge) has a suite of tools for inspecting web traffic.

- **Access:** Press `F12` or `Ctrl+Shift+I`.
    
- **Network Tab:** This is the most critical tab for security testing. It logs every request the browser makes.
    
- **Inspection:** Clicking a specific request allows you to see the raw Headers, the Payload (data sent), and the Response (the data received).
    

Use the **Filter** box in the Network tab to isolate specific requests, such as "XHR" for API calls or "Doc" for the main HTML page.

## HTTP Headers

HTTP headers are the "instruction manual" for a web request or response. They pass critical metadata between the client and the server, defining how data should be handled, identified, and secured.

### Header Categories

Headers are organized based on their role in the communication cycle:

| **Category** | **Description**                                                            | **Key Examples**                 |
| ------------ | -------------------------------------------------------------------------- | -------------------------------- |
| **General**  | Metadata about the message itself, used in both requests and responses.    | `Date`, `Connection`             |
| **Entity**   | Describes the content (payload) being transferred.                         | `Content-Type`, `Content-Length` |
| **Request**  | Sent by the client to provide context about itself or the resource needed. | `Host`, `User-Agent`, `Cookie`   |
| **Response** | Sent by the server to provide context about itself or the result.          | `Server`, `Set-Cookie`           |
| **Security** | Response headers that enforce safety policies in the browser.              | `Content-Security-Policy` (CSP)  |
### 1. General Headers

These headers provide context about the **message itself** rather than its content. They are used in both requests and responses.

- **Date:** The timestamp of when the message was originated (e.g., `Date: Tue, 15 Dec 2023`).
    
- **Connection:** Dictates whether the network connection stays open (`keep-alive`) or closes (`close`) after the transaction.
    

### 2. Request Headers

Sent only by the **client** (browser/cURL) to provide information about the requester or the resource being sought.

- **Host:** Specifies the domain name or IP of the server. This is critical for servers hosting multiple websites on one IP.
    
- **User-Agent:** Identifies the client’s browser, version, and operating system.
    
- **Referer:** The URL of the previous web page from which a link to the currently requested page was followed.
    
- **Accept:** Tells the server which content types the client can understand (e.g., `text/html`, `application/json`).
    
- **Cookie:** Sends stored session data back to the server to maintain authentication or preferences.
    

### 3. Response Headers

Sent only by the **server** to provide more context about the response or the server software itself.

- **Server:** Contains information about the software processing the request (e.g., `Server: Apache/2.4.41`).
    
- **Set-Cookie:** Used by the server to send cookies to the client, which the browser then stores for future requests.
    
- **WWW-Authenticate:** Notifies the client what type of authentication is required to access a restricted resource.
    

### 4. Entity Headers

These describe the **actual payload** (content) being transferred. They are found in both responses and data-heavy requests (like POST).

- **Content-Type:** Defines the media type of the resource (e.g., `text/html`, `image/png`).
    
- **Content-Length:** The size of the message body in bytes.
    
- **Content-Encoding:** Specifies any compression used (e.g., `gzip`) to reduce data size during transfer.
    

### 5. Security Headers

A specific subset of response headers used to instruct the browser on how to handle the site's security policy.

- **Content-Security-Policy (CSP):** Restricts where scripts and resources can be loaded from to prevent XSS.
    
- **Strict-Transport-Security (HSTS):** Forces the browser to communicate only over HTTPS.
    
- **Referrer-Policy:** Controls how much information is leaked in the `Referer` header when navigating away from the site.

### Analyzing Headers with cURL

cURL provides powerful flags to inspect and manipulate headers:

- **`-I` (Head Request):** Fetch and display **only** the response headers. This is the fastest way to check server versions or security policies.
    
- **`-i`:** Display headers **and** the response body.
    
- **`-H`:** Set a custom header (e.g., `curl -H "X-Forwarded-For: 127.0.0.1" [URL]`).
    
- **`-A`:** A shorthand flag specifically for setting the **User-Agent**.

```
# Example: Checking headers for a specific site
mubtasimfuad010101@htb[/host]$ curl -I https://www.inlanefreight.com
HTTP/2 200
server: Apache/2.4.41 (Ubuntu)
content-type: text/html; charset=UTF-8
...
```
### Browser DevTools

In the **Network** tab of your browser (`F12`), clicking on a request opens the **Headers** sub-tab.

- **Request Headers:** What your browser told the server.
    
- **Response Headers:** What the server told your browser.
    
- Use the "Filter" to look for "Security" or specific headers to quickly audit a site's defensive posture.
