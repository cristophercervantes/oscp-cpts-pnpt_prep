### **DNS Structure 

DNS (Domain Name System) is often called the **"phone book of the Internet"**. It translates human-readable domain names (like www.google.com) into machine-readable IP addresses (like 142.250.190.14) and vice versa.

Without DNS, we would have to remember long IP addresses for every website and service.

#### **Main Components of DNS**

- **Name Servers** – Servers that store and provide DNS information.
- **Zones / Zone Files** – Databases containing DNS records for a specific domain (like a local phone book for that domain).
- **Domain Names** – Human-readable names organized in a hierarchy.
- **IP Addresses** – The actual addresses DNS resolves to.

Every system (Linux or Windows) has a local zone file called the **hosts file**:

- Linux: /etc/hosts
- Windows: C:\Windows\System32\drivers\etc\hosts

This file allows local hostname-to-IP mappings before querying real DNS servers.

#### **Domain Name Structure (Hierarchy)**

Domains are organized like a tree (similar to a file system):
```
.
├── com.
│   ├── google.
│   │   ├── www.
│   │   ├── mail.
│   │   └── ns1.
│   ├── example.
│   └── inlanefreight.
│       ├── www.
│       ├── blog.
│       └── dev.
├── net.
├── org.
└── ...
```

**Every domain has at least two parts:**

1. **Top-Level Domain (TLD)** → .com, .net, .org, .io, etc.
2. **Domain Name** → inlanefreight (the actual name you register)

Subdomains (like www, blog, mail, dev) sit under the main domain and can point to different hosts or services.

#### **Types of DNS Servers**

1. **Recursive Resolver (DNS Recursor)**
    - Acts as a middleman between the client (your browser) and the authoritative servers.
    - It performs the full lookup process on behalf of the client.
    - Caches responses to speed up future requests.
2. **Root Name Servers**
    - There are **13 logical root name servers** (A-root to M-root).
    - Maintained by ICANN.
    - They know which TLD name servers to contact for any domain.
    - There are actually hundreds of physical copies worldwide for redundancy.
3. **TLD Name Servers**
    - Manage all domains under a specific TLD (e.g., all .com domains).
    - Managed by IANA.
    - After the root server, the recursive resolver asks the TLD server for the authoritative name server.
4. **Authoritative Name Servers**
    - The final stop in the DNS lookup.
    - They hold the actual DNS records (A, MX, NS, CNAME, etc.) for a specific domain.
    - They provide the real IP address or other records back to the resolver.

#### **DNS Lookup Process (Simplified)**

1. You type www.example.com in your browser.
2. Your device asks the **Recursive Resolver**.
3. Resolver checks its cache → if not found, asks a **Root Name Server**.
4. Root server says: “Ask the .com TLD server”.
5. Resolver asks the **TLD Name Server**.
6. TLD server says: “Ask the authoritative name server for example.com”.
7. Resolver asks the **Authoritative Name Server**.
8. Authoritative server returns the IP address.
9. Resolver caches the result and sends the IP back to your device.

This whole process usually happens in milliseconds thanks to caching.
